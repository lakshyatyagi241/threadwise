## `broadcast_contacts`

**Purpose:** Per-recipient row of a WhatsApp broadcast: which contact, delivery state, provider message id and timestamps.

**Linked to:** broadcasts module (dispatch, progress, receipts, retry sweeper, CSV export, inbox mirror), scheduled-queue-warmer, lead-scoring, wallet-message-billing; web broadcast detail (Recipients/Failures tabs). Reference TW-BCAST-015/025/032.

**Facts:** RLS on+forced · plain · created in `20261001102900_bcast_threadwise_schema.sql` · Drizzle `packages/db/src/schema/broadcasts/tables.ts`

**Design notes:** Hot table: one row per recipient per broadcast; no status CHECK (pending\|processing\|sent\|delivered\|read\|failed per recipient-status.ts). Delivery timestamps overwrite on retry (no event history). Not partitioned although it grows unbounded with sends.

**Purpose:** A WhatsApp (or SMS/Instagram) bulk send: one template to many contacts from a chosen sender, scheduled or immediate, with aggregate delivery/read/click counters.

**Linked to:** broadcasts module (compose, dispatch BullMQ, due sweeper, retry sweeper, receipts, tracking redirect), web /broadcasts list+detail; notifications, dashboards-analytics-charts, plans-subscriptions-trials (usage caps), scheduled-queue-warmer, developer-rest-api-v1. Reference TW-BCAST-001..043.

**Facts:** RLS on+forced · plain · created in `20261001102900_bcast_threadwise_schema.sql` · Drizzle `packages/db/src/schema/broadcasts/tables.ts`

**Design notes:** Mobile-app queue columns (pinned, template_type, temp_image, button_text, latitude, longitude, temp_caption partly) live on this table in Reference "for MOB" and are unused by Threadwise web; the Reference port notes say to move them to a separate queues table. status has no CHECK (scheduled\|processing\|paused\|completed\|completed_with_errors\|failed). Counters are denormalised from broadcast_contacts. device_id is polymorphic with no FK, guarded by trigger trg_broadcasts_check_sender. messages_log jsonb is overloaded (pause note only).
