## `extension_api_tokens`

**Purpose:** API tokens for the Chrome browser extension, per user: only the sha256 hash is stored, with label, last use and a mandatory expiry.

**Linked to:** API addons-extension-registry (extension-token.service issue/resolve/revoke), chrome-extension-sheets-addon login; Reference ext.* api tokens

**Facts:** RLS on+forced · plain · created in `20261001100600_add_threadwise_schema.sql` · Drizzle `packages/db/src/schema/addons-extension-registry/tables.ts`

**Design notes:** Good practice: hash-only storage, always expires (deliberate difference from Reference), expired tokens of the user are purged on issue. NOT NULL expires_at while the resolve query still tests expires_at IS NULL (dead branch). user_id nullable though always set and FK is CASCADE.

## `extensions`

**Purpose:** Platform-wide registry of installed add-on extension modules (uploaded ZIP/manifest): slug, name, version, enable/disable status, installed file list and normalised manifest.

**Linked to:** API addons-extension-registry (extension-store, install/upgrade/enable-disable services), contracts manifest.ts, web install-update-licensing setup screens; Reference extensions / ModuleManager

**Facts:** RLS on+forced · plain · created in `20261001100600_add_threadwise_schema.sql` · Drizzle `packages/db/src/schema/addons-extension-registry/tables.ts`

**Design notes:** Platform table (no org_id; RLS operator_write policy). One row per slug, upserted on upgrade. files and manifest are jsonb with type CHECKs. purchase_code (licence) is written but never read back; installed_by has no FK to platform_operators.
