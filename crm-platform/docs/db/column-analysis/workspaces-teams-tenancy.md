## `impersonation_sessions`

**Purpose:** Audit and control record of a platform operator 'logging in as' a workspace owner (support impersonation): who, where, why, until when, and the one-time handoff code that opens the session.

**Linked to:** API auth/platform (impersonation.service, platform controller), audit; web /impersonate handoff; Reference admin impersonation (WorkspacesController impersonate)

**Facts:** RLS on+forced · plain · created in `20261001102500_wsp_threadwise_schema.sql` · Drizzle `packages/db/src/schema/workspaces-teams-tenancy/tables.ts`

**Design notes:** Platform-only table (RLS policy operator_write via app_is_privileged, no org_id column). Reworked vs the baseline (original_workspace_id/admin_user_id replaced by operator_id/target_user_id). Good invariants: one open session per operator (partial unique), ended_at/ended_by pair CHECK, expires_at > started_at. No retention policy; old sessions are legitimate audit evidence so keep. handoff_expires_at NOT NULL while the hash is nullable (hash is never nulled in code, only protected by handoff_used_at).

**Facts:** RLS on+forced · plain · created in `20261001102500_wsp_threadwise_schema.sql` · Drizzle `packages/db/src/schema/workspaces-teams-tenancy/tables.ts`

**Design notes:** Design smell: a 'settings' god-row (50 columns, mixed concerns) mirroring Reference `workspaces`. At least 21 columns have no production reader or writer (caps, branding_*, custom_domain, billing_cycle, trial/plan dates, plan_overrides, voice delays, deals_auto_*, ...) because the port stores the same facts elsewhere: org_plan_state (plan window, overrides, data_wiped_at), organizations.settings jsonb (branding, notificationPrefs, ownerUserId, timezone, currency) and storefront shops (custom_domain). Split-brain risk: SLA/flow/routing read workspace_settings.timezone/business_hours/inbox_away, but the Settings UI writes timezone into organizations.settings, and nothing in apps/api writes workspace_settings.timezone, business_hours or inbox_away. Several columns are text holding JSON (business_hours, plan_overrides, notification_prefs, appointment_settings, auto_translate_languages) instead of jsonb. Row is created lazily by upserts; readers must handle a missing row. Recommend: delete dead columns, move business_hours/timezone/inbox_away to a single owner, convert JSON text to jsonb.
