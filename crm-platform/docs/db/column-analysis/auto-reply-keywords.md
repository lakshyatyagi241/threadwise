## `auto_reply_lookups`

**Purpose:** Audit row for every inbound text the WhatsApp (Baileys) bot asked the auto-reply lookup about, matched or not; feeds the match-rate chip and latency KPI. Monthly RANGE partition on created_at.

**Linked to:** admin-console-shell overview-stats.service (match % chip); plan-retention wipe list; Reference TW-AR-030/036 lookup endpoint (not built in Threadwise yet).

**Facts:** RLS on+forced · partitioned · created in `20261001103200_ar_threadwise_schema.sql` · Drizzle `packages/db/src/schema/auto-reply-keywords/tables.ts`

**Design notes:** Highest-volume table of the domain, never pruned in Reference: needs retention/partition drop. contact_phone and query_text were Laravel-encrypted in Reference but are plain text here (PII: customer number and raw message). No FK on device_id / matched_keyword_reply_id (partitioned table; app-enforced). Nothing writes it yet but the overview reads it, so the match % chip always shows empty.
