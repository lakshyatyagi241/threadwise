# Wiring map: contacts list, quick view and details page redesign (CON, owner-requested extension)

Scope: the screen layer of `/contacts` (Contact Hub), the new quick-view drawer (`/contacts?contact=<id>`) and `/contacts/<id>[/<section>]`.
Every API, table and permission below already exists; this change adds **no migration, no endpoint and no contract**. It re-lays the
screens and wires the already-built contact notes, meetings, files, activities, deals and field-history endpoints that had no web consumer.

Why this is not a "same UI as Reference" screen: the owner asked for the patterns of their own company platform (the screens of
geta-platform, read from the owner's browser: layout only, no code or assets) to replace the Contact Hub's busy toolbar. That is a documented,
owner-requested extension (Extension 2 of [product-extensions.md](../parity/product-extensions.md) is superseded for the toolbar only).
Parity rows: [parity/contacts-attributes-tags.md](../parity/contacts-attributes-tags.md), section "Contacts list, quick view and details redesign".
Earlier maps that stay true: [contact-owner.md](contact-owner.md), [contact-consent.md](contact-consent.md), [companies.md](companies.md).
