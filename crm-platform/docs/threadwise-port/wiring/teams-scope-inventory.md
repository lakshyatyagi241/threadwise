# Teams scope inventory (BL-380, teams T0)

Every place that decides "which records may this person see or act on" from a record scope (`own` | `team` | `all`) or from team
membership, as found on `origin/main` on 2026-10-19 and as moved by BL-380. Spec: `docs/specs/teams-unification.md` (sections 2, 3, 5.2, 6).
Backlog: `docs/backlog.md` BL-380.

## The resolver

`apps/api/src/kernel/rbac/scope/` (barrel `index.ts`), the only code that writes the team self-join or the own/team/all switch:

| Export                                                                      | Use                                                                                                                                                   |
| --------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `scopeOwnerCondition(actor, scope, columns)`                                | A WHERE fragment for a list. `columns` is EVERY column that names a person on the record (owner, assignee, host, creator). `all` returns `undefined`. |
| `scopeOwnerPredicate(actor, scope, columns)`                                | The same, never NULL (`COALESCE(..., FALSE)`), for a record reached by `LEFT JOIN`.                                                                   |
| `canActOn(tx, actor, scope, people)` / `ScopeResolver.canActOn`             | One record already loaded: the same answer the list gives.                                                                                            |
| `teamPeers(tx, actor)` / `teamIdsOf(tx, actor)` / `isTeamPeer(...)`         | Teammates and team ids; cached for the life of the transaction, never across requests.                                                                |
| `teamPeersSql`, `memberTeamIdsSql`                                          | The sub-selects, for code that builds its own SQL (segment shares).                                                                                   |
| `conversationScopeCondition(viewer, alias)` / `conversationScopeAllows(..)` | The inbox's own rule, the explicit `conversation` mode.                                                                                               |

Meaning, in every module (decision D1 applied): `own` = any person column is me, creator included. `team` = `own`, or any person column is
a member of a team I am in (a person in no team still sees their own). `all` = no condition. No signed-in person = nothing below `all`.
Conversation mode: `own` = assigned to me; `team` = assigned to me or to one of my teams, plus the unassigned queue for a viewer who holds the permission
`inbox.conversation.read_unassigned` (T2, BL-382); `team_and_below` = the same with the teams below mine; `all` = everything. T2 added `team_and_below` to `scopeOwnerCondition`, `canActOn`
and the conversation mode: see [teams-t2.md](teams-t2.md).

## Known gaps not in T0

- Flow Assign nodes keep a team uuid in their definition; deleting a team does not clean them (the preview does not count them).
- A person on two teams used to be counted twice in team reports; fixed in T2 (BL-382): reports by team read `owning_team_id` or the owner's primary team, see [teams-t2.md](teams-t2.md).
