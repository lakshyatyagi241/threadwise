# Wiring map: team-inbox-routing-sla (TIB2), auto-assignment rules

| What                       | Where                                                                                                                                                                                                                                                              |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Route (web)                | `/auto-assignment`, `/auto-assignment/new`, `/auto-assignment/:id`; Settings tile `auto-assignment` (Automation), shortcut from `/inbox`                                                                                                                           |
| Route (API)                | `/v2/inbox/routing/rules*`, `/v2/inbox/routing/settings`                                                                                                                                                                                                           |
| Permissions                | read `inbox.settings.read`; write `inbox.routing.manage` (existing keys)                                                                                                                                                                                           |
| Plan                       | feature `inbox_routing` (all routes, reads included); limit `routing_rules` (create, duplicate)                                                                                                                                                                    |
| Tables                     | `routing_rules` (conditions, actions incl. description and `rrCursor`, `sort`, `fired_count`, `last_fired_at`), `workspace_settings.routing_keep_contact_agent`; reads `contacts`, `conversations`, `users`, `teams`, `team_members`, `agent_statuses`, `channels` |
| Upstream feeders           | inbound pipeline: `InboundMessageHooks` listener `team-inbox-routing` (worker only), event now carries `reopenedFrom`; business hours from `workspace_settings.business_hours` via `common/business-hours.ts` (shared with the flows)                              |
| Downstream                 | `AssignmentService.assignInTx/afterCommit`: timeline, audit, `conversation.assigned` outbox event, realtime, mine/unassigned counters                                                                                                                              |
| Consumers of the same data | segments rule engine (`compileRules`) for the contact condition; assignee picker (`GET /inbox/assignees`) for the form                                                                                                                                             |
| Worker                     | `TeamInboxRoutingSlaWorkerModule` in `WorkersModule`                                                                                                                                                                                                               |
| Not built                  | routing actions other than assign, sticky/team strategy, capacity, follow-up filtering, device condition (see the inventory port note)                                                                                                                             |

## Phase 3 slice: bulk, priority, snooze (WIRE-TIB-PH3)

| What         | Where                                                                                                                                                                                                                                 |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Routes (API) | `POST /v2/inbox/conversations/bulk`, `POST /v2/inbox/conversations/:id/priority`, `POST /v2/inbox/conversations/:id/snooze`                                                                                                           |
| Permissions  | `inbox.conversation.bulk` plus the action's own key (resolve, assign or assign_self, read, priority, snooze); `inbox.conversation.priority`; `inbox.conversation.snooze`                                                              |
| Tables       | `conversations` (`priority`, `snoozed_until`, `status`), `conversation_events` (`priority_changed`, `snoozed`, `auto_unsnoozed`), `audit_log` (`conversations.bulk`), outbox `conversation.priority_changed`, `conversation.reopened` |
| Worker       | `TeamInboxConversationsWorkerModule` > `InboxSnoozeWakeService` (every 30 s, wakes due snoozed threads)                                                                                                                               |
| Web          | `bulk-bar.tsx`, `use-bulk.ts`, `lib/selection.ts`, `triage-menu.tsx`, list Select mode in `conversation-list.tsx` and `conversation-row.tsx`                                                                                          |
| Not built    | bulk label, spam, archive, pin, mute, delete; conversation labels; SLA timers, breach badge and notification; retention. Design: `docs/specs/inbox-phase3-slice.md`                                                                   |
