## Tags (formerly "Labels") (WIRE-TIB-TAGS)

One concept, one word: the reference calls them tags, and the earlier name "labels" was ours and is retired. Same tables, no migration.

| Id               | What                 | Where                                                                                                                                                                                                                                                                                                                |
| ---------------- | -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| WIRE-TIB-TAGS-01 | Library routes (API) | `GET/POST /v2/inbox/tags`, `PATCH/DELETE /v2/inbox/tags/:id` (`inbox.conversation.read` to read, `inbox.tag.manage` to change); the original `/v2/inbox/labels*` paths are registered as aliases on the same handlers                                                                                                |
| WIRE-TIB-TAGS-02 | Thread routes (API)  | `POST /v2/inbox/conversations/:id/tags`, `DELETE .../tags/:tagId` (`inbox.conversation.tag`); `.../labels` aliases kept                                                                                                                                                                                              |
| WIRE-TIB-TAGS-03 | List filter (API)    | `GET /v2/inbox/conversations?tags=<id>,<id>&tagScope=conversation\|contact`; `?labels=` is merged with `tags`; `tagScope=contact` matches the contact's tags through `contact_tags` (`EXISTS`, indexed on `org_id, contact_id`, same org match as the other filters)                                                 |
| WIRE-TIB-TAGS-04 | Bulk action          | `{type: 'tag', mode, tagId}`; `{type: 'label', ...}` still accepted (same handler, same permission `inbox.conversation.tag`)                                                                                                                                                                                         |
| WIRE-TIB-TAGS-05 | Detail: contact tags | `GET /v2/inbox/conversations/:id` returns `contactSummary.contactTags` (id, name, color; empty when the caller may not read contacts or the thread has no contact)                                                                                                                                                   |
| WIRE-TIB-TAGS-06 | Events and audit     | timeline `tag_added` / `tag_removed`, outbox `conversation.tag_added` / `conversation.tag_removed` (always had the tag name, unchanged; no consumer used a `label` name); audit delta key is now `tags` (was `labels`); realtime `changed` carries both `tags` and `labels`                                          |
| WIRE-TIB-TAGS-07 | Wire names kept      | the conversation JSON field stays `labels` (holds the tags); error codes stay `INBOX_LABEL_NOT_FOUND` and `INBOX_LABEL_CREATE_FORBIDDEN` (the messages say tag)                                                                                                                                                      |
| WIRE-TIB-TAGS-08 | Web screens          | `/inbox/tags` (Settings tile `inbox-tags`, "Conversation tags"; `/inbox/labels` redirects), the header `Tag` menu, the side panel `tag-groups.tsx` (**Contact tags** read-only with "Edit on contact", **Conversation tags** add/remove), the list `tag-filter.tsx` with the Conversation tags / Contact tags switch |
| WIRE-TIB-TAGS-09 | Web address          | `/inbox?tags=<id>,<id>&tagScope=contact`; `?labels=` is still read and rewritten to `tags` on the next filter change                                                                                                                                                                                                 |
| WIRE-TIB-TAGS-10 | Help                 | `inbox-tags` (was `inbox-labels`, tile `inbox-tags`), `team-inbox-overview` and `contacts-overview` each carry "Tags: contact tags vs conversation tags"; Arabic versions `*.ar.md`                                                                                                                                  |
| WIRE-TIB-TAGS-11 | Consumers checked    | outbound webhooks, flows and campaigns use `tags` / contact tags only; nothing listens for an `inbox.label.*` event (none was ever emitted)                                                                                                                                                                          |

## Business hours (WIRE-TIB-BH)

The weekly schedule and the workspace zone that the routing condition, the SLA clock and the flows read. Set on the Auto-assignment screen.

| Id             | What                                 | Where                                                                                                                                                                                                                                                                                                                                                                       |
| -------------- | ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| WIRE-TIB-BH-01 | Routes (API)                         | `GET /v2/inbox/routing/business-hours` (`inbox.settings.read`), `PUT /v2/inbox/routing/business-hours` (`inbox.routing.manage`, Idempotency-Key); plan feature `inbox_routing` on the whole controller; `business-hours.service.ts`, pure rules in `business-hours-rules.ts`                                                                                                |
| WIRE-TIB-BH-02 | Web                                  | "Business hours" button on `/auto-assignment` (Settings > Automation > Auto-assignment) opens `business-hours-dialog.tsx`; `lib/business-hours.ts`; help guide `auto-assignment.md`. Reference's modal also held the outside-hours reply and anti-spam fields: not in this slice (WIRE-TIB-BH-06)                                                                           |
| WIRE-TIB-BH-03 | Tables and writes                    | `workspace_settings.business_hours` (JSON text: `days` replaced; other keys kept as they are; row upserted), `organizations.settings.timezone` (owner only: the zone the owner's profile sets too; a non-owner's zone is ignored, not an error); audit module `business_hours` (action `update`); outbox `business_hours.updated` (no consumer yet)                         |
| WIRE-TIB-BH-04 | Readers, same zone                   | `RoutingRulesRepository.businessHours` (the engine's `outside_business_hours` check, `RoutingEngine`); `SlaClockService` (`respectBusinessHours` policies). Both read the zone from `organizations.settings.timezone`, the one the owner sets; before this change they read `workspace_settings.timezone`, which nothing writes, so a workspace in India was checked in UTC |
| WIRE-TIB-BH-05 | Readers, NOT yet on the owner's zone | `flow-runtime-engine/triggers/trigger.service.ts` (out-of-hours trigger, TW-FLR-007), `leads/lead-first-message.lookups.ts` (WIRE-LEAD-028 business hours), `platform-support-desk/sla.service.ts`: they still read `workspace_settings.timezone` (always UTC). Same bug, other zones: fix in their own change                                                              |
| WIRE-TIB-BH-06 | Not built                            | the outside-hours template auto-reply (TW-TIB2-002) and the anti-spam cooldown and threshold (TW-TIB2-003). The dialog does not show them; a save keeps the stored keys                                                                                                                                                                                                     |
