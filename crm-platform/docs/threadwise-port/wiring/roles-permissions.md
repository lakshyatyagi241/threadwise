# Wiring map: roles-permissions (RBAC)

Read with [the inventory entry](../inventory/roles-permissions.md). One row per feature: where it lives in Reference, what feeds it, what
consumes it, and where it lands in our code. `built` = in this repo and tested; `blocked:<id>` = waits on a feature another domain owns
(the id is the one to unblock); `intended` = deliberately different (reason in [parity/roles-permissions.md](../parity/roles-permissions.md)).

Two authorization systems are ported here and kept apart, as in Reference:

|                     | Platform layer (operator console)                                            | Workspace layer (customer organizations)                         |
| ------------------- | ---------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| Who                 | `platform_operators` (SaaS staff)                                            | `users` of an organization                                       |
| Roles               | `platform_roles` (global, editable, 6 seeded)                                | `roles` per organization (five Reference presets seeded per org) |
| Permission registry | `platform_permissions` (101 Reference keys, free text)                       | `permission_defs` (global, code-defined dotted keys)             |
| Grants              | `platform_role_permissions`, `platform_operator_roles`                       | `role_grants` (allow/deny, record scope), `user_roles`           |
| Cache               | `prbac:v<rbac.version>:op<id>`, version in `platform_settings`               | `rbac:<org>:v<roles_version>:u<user>`                            |
| Guard               | `@UseGuards(OperatorGuard, PlatformPermissionGuard)` + `@PlatformPermission` | `PermissionsGuard` + `@RequirePermission`                        |
| Code                | `apps/api/src/modules/roles-permissions`                                     | `apps/api/src/kernel/rbac`, `apps/api/src/modules/admin`         |

The legacy `users.role` string (TW-RBAC-017) has no equivalent and is not ported: suspension is `status`, platform-admin recognition is
the operator identity pool, plan/billing bypass belongs to the PLAN and BILL domains as an explicit flag.
