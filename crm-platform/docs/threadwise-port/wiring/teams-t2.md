# Wiring map: Scope semantics and the owning team (BL-382, phase T2 of the teams unification)

Read with [specs/teams-unification.md](../../specs/teams-unification.md) (sections 5.2, 5.3, 5.5, 6 T2, decisions D1, D2, D8), the code map of the resolver
[teams-scope-inventory.md](teams-scope-inventory.md) (T0), [teams-v2.md](teams-v2.md) (T1) and the API doc [api/teams-scope.md](../../api/teams-scope.md).

## Migrations (all expand-only, all pass `deploy/build-server/migration-lint.py` with exit 0)

| File                                                  | What                                                                                                                                                                                                                                                                                                                                                         |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `20270225090000_record_scope_team_and_below.sql`      | `ALTER TYPE record_scope ADD VALUE IF NOT EXISTS 'team_and_below'`. First line `-- @no-transaction` (the repo precedent for `ADD VALUE`: the runner then sends the file outside a `BEGIN`; one statement per file), plus a reviewed `-- bluegreen-ok:` line because the lint flags every `ALTER TYPE`: appending a value changes no row the live slot reads. |
| `20270225090100_inbox_read_unassigned_permission.sql` | Registers `inbox.conversation.read_unassigned` (no scope), Viewer preset baseline row, grants it to every role with `inbox.conversation.read` allow at `team`, bumps `roles_version` (privileged flag set first, like every migration that touches `organizations`).                                                                                         |
| `20270225090200_owning_team_id.sql`                   | `owning_team_id` on `contacts`, `companies`, `deals`, `tasks` (nullable, composite FK `(org_id, owning_team_id)` to `teams (org_id, id)` with `ON DELETE SET NULL (owning_team_id)`, added `NOT VALID`), `owner_primary_team(org, user)`, trigger function `stamp_owning_team()` and one trigger per table. `deals.owner_team_id` untouched.                 |
| `20270225090300_owning_team_id_validate.sql`          | `VALIDATE CONSTRAINT` of the four foreign keys (lock that does not block writes).                                                                                                                                                                                                                                                                            |
| `20270225090401..04_<table>_owning_team_idx.sql`      | `CREATE INDEX CONCURRENTLY idx_<table>_owning_team (org_id, owning_team_id) WHERE owning_team_id IS NOT NULL`, one statement per file, `-- @no-transaction`.                                                                                                                                                                                                 |

## Not in T2 (and where it goes)

- `teams.is_scope_boundary` is still stored and not read (no spec rule says what a non-boundary team does).
- Dropping `deals.owner_team_id` and `team_members.is_lead` (kept for the release still serving traffic): a contract migration in a later release (BL-382 follow-up).
- Companies have the column and the API filter is not added (the spec lists contacts, deals and tasks lists); a companies Team filter is a small follow-up.
- Invoices, sales documents and appointments carry no stamp: their reports by team read the owner's primary team.
- Plan gate key `team_hierarchy`, the `teams` limit and `custom_roles`: T3 (BL-383). The matrix helper treats a missing key as on until that merges.
