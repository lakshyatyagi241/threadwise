# Wiring map: privacy and personal-data register (PRIV), a product extension

Not a Reference feature. Spec: [privacy-and-data-governance.md](../../specs/privacy-and-data-governance.md); differences go in
`docs/threadwise-port/parity/product-extensions.md` when something ships. Update this file in the same change as any new table, storage
prefix, vendor call or export that touches a person's data.

This is the **seed of the DSAR registry** (spec 4.5): one row per place personal data lives, with a stable `Key`, so a generator can
turn it into the typed manifest and the failing test. Columns: Module (path under `apps/api/src/modules` unless stated), Data, Subject
(C contact, L lead, E end customer, S staff, V visitor), Table or store (migration names where verified; `inferred` otherwise), Link
(how the row ties to a person), On contact delete (today), Export handler, Erase handler, Retention, Status (`registered` = declared in
code manifest, none yet; `todo` = to register). Evidence for "today" columns is in the spec, section 2.

**State after BL-142 / BL-143 (this supersedes the per-row Export, Erase and Status cells below for every key listed here).** The registry
is code: `apps/api/src/modules/privacy/manifests/*.ts` (typed `HolderManifest`, handlers `export` and `erase` generated by `defineHolder`),
enforced by `apps/api/test/integration/privacy/registry.spec.ts` against the migrated schema. 18 holders, 95 registered tables; of the 120
tables the test finds pointing at a person, 90 are registered and 30 sit in `registry/allowlist.ts` with a written reason (staff, workspace
settings, platform data, one follow-up: `companies`). The rows below that are NOT in this list are still `todo`.

## Storage prefixes to register (inferred, confirm)

Chat media, contact files, call recordings, consent export files, training files, branding, invoice PDFs. The purge queue is the
delete mechanism; the registry will name each prefix and the owning key.

checklist ([privacy-by-design-checklist.md](../../../docs/privacy/privacy-by-design-checklist.md)), and the sub-processor register.
