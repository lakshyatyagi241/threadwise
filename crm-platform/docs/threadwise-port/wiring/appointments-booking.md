# Wiring map: Appointments and booking (TW-APPT), calendars (BL-035)

Reference: `BookingTypeController`, `AppointmentController`, `PublicBookingController`, `GoogleCalendarOAuthController`, `BookingReminderJob`, the Book appointment flow node. The inventory is
[inventory/appointments-booking.md](../inventory/appointments-booking.md); the API is [docs/api/appointments-booking.md](../../api/appointments-booking.md). This file is the record of who feeds
the domain and who reads it, so a consumer is not lost between screens. The calendar rows (BL-035: Outlook, iCal, back-fill, tools) are new since the first port and are added here with ids
`WIRE-APPT-*`.

| What             | Where                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Route (web)      | `/appointments`, `/appointments/types`, `/appointments/booking-types/*` (editor), `/appointments/settings` (calendar cards), public `/book/<workspace>/<service>` and `/b/manage/<token>`                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Route (API)      | `/v2/booking-types`, `/v2/appointments` (+ `/calendar/*`), `/v2/public/booking/*`, `/v2/public/booking-manage/*`, `/v2/public/appointments/calendar/{google,microsoft}/callback`, `/v2/public/appointments/feed/<token>.ics`                                                                                                                                                                                                                                                                                                                                                                                     |
| Permissions      | `record.booking-types.{read,create,update,delete}`, `record.appointments.{read,create,update,delete}` (migration `20261012090100`); the calendar cards need `record.booking-types.update` (connect, choose, feeds, back-fill) or `record.appointments.read` (overview, a person's own bookings feed); Google also `google.account.{read,manage}`                                                                                                                                                                                                                                                                 |
| Plan             | `appointment_booking` (every staff route and the public page), the `appointments` monthly cap; no plan key for calendars (Reference's `integration_google_calendar` has none here)                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Tables           | `booking_types` and children, `appointments` (+ `calendar_event_id`, `calendar_id`, `calendar_provider`, `google_*` sync columns), `appointment_reminder_runs`, `appointment_calendar_connections` (Google), `appointment_microsoft_connections` (Outlook), `appointment_calendar_preferences` (where bookings are written), `google_consent_requests`, `calendar_ics_feeds` and `calendar_ics_busy` (iCal subscriptions), `appointment_feed_tokens` (a person's bookings feed)                                                                                                                                  |
| Settings         | console groups `googleCalendar` and `microsoftCalendar` (client id, secret, tenant, redirect, master switch); env `GOOGLE_CALENDAR_*`, `MICROSOFT_CALENDAR_*`, `ICS_FEED_*` ([runbooks](../../runbooks/microsoft-calendar-setup.md)); the workspace's time zone (`organizations.settings.timezone`) cuts days and reads floating times of a feed                                                                                                                                                                                                                                                                 |
| Upstream feeders | the public booking page; staff booking; the flow runtime's Book appointment node (`BookingOffersService`); the platform operator's Google and Microsoft apps; the remote calendars (Google, Outlook, ICS feeds); the worker's sweeps                                                                                                                                                                                                                                                                                                                                                                             |
| Downstream       | outbox `appointment.*` (message consumer, calendar consumer, flow trigger `appointment_booked`, drift notification), `appointment_calendar.*` (back-fill consumer), `calendar_ics_feed.*`, `appointment_feed.*`; audit modules `appointments`, `booking_types`, `appointment_calendar`, `appointment_calendar_microsoft`, `appointment_calendar_preference`, `appointment_calendar_backfill`, `calendar_ics_feed`, `appointment_feed`; queues `calendar-reconcile`, `calendar-backfill`, `calendar-ics-refresh`; the slot engine (busy time from every source); customer messages through `AppointmentMessenger` |

## BL-035 rows (what each new piece feeds and what reads it)

| Id            | What                                                                                                                    | Fed by                                                                                                   | Read by                                                                                                                                                                                        |
| ------------- | ----------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| WIRE-APPT-001 | Outlook / Microsoft 365 provider behind the calendar port (`MicrosoftCalendarAdapter`)                                  | the operator's Entra app (console group `microsoftCalendar`), the admin's consent + confirm              | `MultiCalendarAdapter` (busy time from every connected calendar; events to ONE), `AppointmentCalendarWriter`, the slot engine through `SlotsService.busyFor`, the settings page (Outlook card) |
| WIRE-APPT-002 | Where bookings are written (`appointment_calendar_preferences`, `PUT /appointments/calendar/provider`)                  | an admin's choice; automatic otherwise (Google when usable, else Microsoft)                              | `CalendarProviders.writeProvider` (writer, back-fill, status), the settings page (write target card)                                                                                           |
| WIRE-APPT-003 | `appointments.calendar_provider`: which provider holds an event                                                         | `AppointmentCalendarWriter`                                                                              | the writer (moves an event when the provider changes), the Google reconcile (reads only Google events), `detachEvents` (a replaced account), the back-fill candidates                          |
| WIRE-APPT-004 | Back-fill of calendar events (queue `calendar-backfill`)                                                                | outbox `appointment_calendar.connected` and `.provider_selected`; `POST /appointments/calendar/backfill` | `AppointmentCalendarWriter.sync`; audit `appointment_calendar_backfill`; outbox `appointment_calendar.backfilled`; `backfillPending` in the overview                                           |
| WIRE-APPT-005 | iCal subscriptions as a read-only busy source (`calendar_ics_feeds`, `calendar_ics_busy`, queue `calendar-ics-refresh`) | the admin's feed address (sealed), the worker's 15-minute read                                           | `IcsBusySource` through `MultiCalendarAdapter.freeBusy` (every slot lookup: staff, public page, flows, tools); the settings page (feeds card)                                                  |
| WIRE-APPT-006 | A person's bookings as an ICS subscription (`appointment_feed_tokens`, `GET /public/appointments/feed/<token>.ics`)     | the person (Make my link), the bookings list scope at read time                                          | a calendar app; the settings page (my bookings card)                                                                                                                                           |
| WIRE-APPT-007 | Booking tools for agents and chatbots (check availability, book, reschedule)                                            | see the tool contract in `docs/api/appointments-booking.md`, "Tools for agents and chatbots"             | **Not bound to any agent yet** (BL-196): the customer-facing AI paths have no tool-calling loop                                                                                                |

## Not built, recorded

- The hourly drift check reads Google events only; Outlook drift is BL-195.
- Per-booking-type Outlook calendar; Teams links for personal Microsoft accounts.
- A watch channel or delta query for Outlook and for iCal (the fixed 15-minute read replaces them).
- Real-account verification of Google and Microsoft (BL-194): everything here is exercised against local stand-ins written from the vendors' documentation.
