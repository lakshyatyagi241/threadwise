# Wiring: message delivery log, archive and export (platform addition)

Not a Reference feature: added because a message that Meta accepted and then refused (error 131049) looked `sent` after an agent pressed Retry, with no way to see why.
It adds no screen of Reference and changes none of its behaviour.

| Piece                         | Where                                                                                                                                                                                                                                  |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tables                        | `message_event_archives`, `message_log_exports` (migration `20261116100000_message_log_archive`, RLS forced); `message_events` unchanged (+ `created_at` index)                                                                        |
| Permission                    | `inbox.logs.export` (workspace Admin preset); reading one message's log needs `inbox.conversation.read`                                                                                                                                |
| Contracts                     | `packages/contracts/src/chat-conversations/message-log.ts`; errors `MESSAGE_LOG_EXPORT_*`                                                                                                                                              |
| API                           | `modules/chat-conversations/message-log*.ts` (service, repository, rules, archive sweep, export runner/processor/publisher, `MESSAGE_LOG_FACADE`); routes in `team-inbox-conversations/inbox.controller.ts` (`InboxMessageLogService`) |

| Web                           | `features/team-inbox-conversations`: `MessageLogDialog` (bubble list icon and the failure line), `MessageLogsScreen` at `/inbox/message-logs`, Settings tile `message-logs` (Data and security), help guide `message-logs`             |

## Message History screen (Reference `/message-history`, TW-CHAT-039 to -042)

Reference's History screen is built on this log's neighbours: the message stream, the delivery log and the same export queue. It adds the screen below; the log, archive and export above are unchanged except where a row says so.

| Piece                    | Where                                                                                                                                                                                                                                                                                                                                     |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Route and nav            | `/message-history`; Campaigns > History (`features/message-history/nav.ts`, id `history`; the planned entry in `_registry/planned.ts` was removed). More page card `message-history` (`admin-console-shell`) already links here; its count (`overview-stats.service.ts`) is the raw `messages` count, not the feed's total                |
| Permissions              | `msg.history.read` (new, Manager preset and up, migration `20261126090000_message_history`); rows by the caller's `inbox.conversation.read` scope (`visibleToSql`); numbers by `record.contacts.read` scope; cost by `wallet.statement.read`; export `inbox.logs.export` + read scope `all`                                               |
| Tables read              | `messages`, `conversations`, `contacts`, `channels`, `wa_templates`, `users`, `usage_charges` (cost, by provider message id), `broadcast_contacts` + `broadcasts`, `wp_campaign_contacts` + `wpcampaigns`, `scheduled_message_contacts` + `scheduled_messages`, `message_event_archives` (through the log)                                |
| Tables written           | none by the screen. Export: `message_log_exports` gained `kind` (`events`, `messages`) and `filters` (jsonb)                                                                                                                                                                                                                              |
| Indexes                  | `idx_broadcast_contacts_org_at`, `idx_wp_campaign_contacts_org_at`, `idx_scheduled_message_contacts_org_at`: `(org_id, COALESCE(sent_at, created_at) DESC, id DESC)`, so the feed's order is an index scan                                                                                                                                |
| Contracts                | `packages/contracts/src/chat-conversations/message-history.ts`; `messageLogExportSchema` gained `kind`; `listMessageLogExportsQuerySchema`                                                                                                                                                                                                |
| API                      | `team-inbox-conversations/message-history.{controller,service}.ts`; `chat-conversations/message-history{.query,.repository,-rules,-export}.ts`; `MessageLogFacade.requestHistoryExport`; the list of exports takes `?kind=`                                                                                                               |
| Worker                   | `MessageLogExportRunner.buildMessages` (the same `msg-log-export` job, `kind = 'messages'`); the "ready" email links to `/message-history?export=<id>`                                                                                                                                                                                    |
| Feeders                  | `ConversationsFacade.recordOutbound` / the inbound pipeline (`messages`); `BroadcastInboxMirrorService` and `CampaignMirrorService` (the mirrored bubble is left out of the feed; the campaign mirror now writes `meta.campaign_id` so it can be recognised); broadcast, campaign and scheduled sends (recipient rows and their receipts) |
| Web                      | `features/message-history`: `MessageHistoryScreen` (cards, volume chart, direction ring, filters in the address, table, drawer, type mix, top conversations, export status), help guide `message-history`; the drawer draws the log with `MessageLogTimeline` (extracted from `MessageLogDialog` in `team-inbox-conversations`)           |
| Consumers of the changes | `MessageLogsScreen` (lists `kind=events` only, as before); `MessageLogDialog` (same output, now via `MessageLogTimeline`); the campaign mirror's `recordOutbound` call (one more `meta` key)                                                                                                                                              |
