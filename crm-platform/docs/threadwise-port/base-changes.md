# Base changes: Reference's base versus this repo's base

What Reference assumes underneath every feature, what `crm-platform` had, and what was done about it. "Done" means merged in the
`feat/monorepo-web-base` branch and verified; everything else names the owner (see [assignments.md](assignments.md)) and the
decision it waits for. Sources: [target-map.md](target-map.md) (target facts), the `admin-console-shell`, `localization-translation`
and `auth-registration-security` inventory files (Reference facts).

## Monorepo shape

| Before                                                                                             | Now                                                                                                                                                             |
| -------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Backend monorepo (API, worker, db, contracts). `apps/web` and `apps/partner` were READMEs only     | `apps/web` (`@crm/web`, Next.js 16 App Router) and `packages/ui` (`@crm/ui`) are real workspace packages, built, linted, typechecked and tested by turbo and CI |
| API Dockerfile copied four manifests by name                                                       | Also copies the web and ui manifests, so the frozen-lockfile install keeps working                                                                              |
| No root script for the frontend                                                                    | `pnpm dev:web` (port 3001, matching `CORS_ORIGINS` in `.env.example`)                                                                                           |
| CI checked the backend only                                                                        | CI also builds the web app                                                                                                                                      |
| Not done: a web Dockerfile and a compose service; `apps/partner` (sub-agent portal) stays a README | `lakshya` (F0/F1), when deployment is decided                                                                                                                   |

## What changed, precisely

- New: `packages/ui`, `apps/web` (config, i18n, proxy and session routes, nav registry, two shells, login, dashboard, contacts list).
- Edited (shared files, each a small additive change): `.github/workflows/ci.yml`, `apps/api/Dockerfile`, `.env.example`, `.gitignore`,
  `.prettierignore`, `eslint.config.mjs`, `package.json`, `turbo.json`, `pnpm-lock.yaml`,
- Not touched: the API, the worker, the database, `@crm/contracts`.

## Verified

Against the real API and the seeded dev database: typecheck, lint, 14 unit tests and a production build pass; unauthenticated
`/dashboard` redirects to `/login`; a wrong password returns the API's problem+json; a good login sets two httpOnly cookies; the
contacts screen loads 26 seeded rows over the cursor envelope in a real browser; `auth/*` through the proxy returns 404; a
cross-origin write returns 403; locale `ar` renders `dir="rtl"`; logout ends the session.

Not verified: token refresh after the access token expires, the mobile drawer on a real phone, Windows, a production deployment.
