## Intended differences from Reference

| #   | Area                   | Reference                                                                          | Here                                                                                                                                                                                                        |
| --- | ---------------------- | ------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Access                 | Workspace role plus plan flags                                                  | Permission keys `fb.pages.read`, `fb.pages.manage`, `fb.broadcasts.*`, `fb.setup.manage`, `fb.posts.*`, `fb.insights.read`.                                                                                 |
| 2   | Login round trip       | PHP session CSRF token as `state`; `/facebook/connect` is a GET redirect        | `POST /facebook/connect/start` returns the address; `state` is a sealed value naming organization and user, good for 15 minutes; the callback is public and redirects to the hub with `fb` and `message`.   |
| 3   | Webhook address        | `/webhooks/facebook`                                                            | `/v2/facebook/webhook`. The address in the Meta app must be changed once.                                                                                                                                   |
| 4   | Meta app settings      | `SystemSetting` keys (`fb_app_id`, `waba_app_id` ...)                           | Environment: `FB_APP_ID` or `META_APP_ID`, `FB_APP_SECRET` or `WHATSAPP_APP_SECRET`, `FB_WEBHOOK_VERIFY_TOKEN` or `WHATSAPP_VERIFY_TOKEN`, `FB_CONFIG_ID`, `FB_GRAPH_VERSION`. Same fallback order.         |
| 5   | Ids                    | Numeric database ids in URLs                                                    | Uuids.                                                                                                                                                                                                      |
| 6   | Backfill               | A hook after the response                                                       | A queue job (`fb-backfill`).                                                                                                                                                                                |
| 7   | Token sweep            | Inline, once an hour per workspace, on Channels page load                       | An hourly worker job over every organization that has a Page.                                                                                                                                               |
| 8   | Sender name            | Resolved before the contact is created                                          | The thread starts as "Facebook user" and is renamed right after (thread, contact name and picture); the end state is the same.                                                                              |
| 9   | Sender profile cache   | Cached six hours                                                                | Not cached: it is fetched once when a thread is created, so a cache could only matter after a thread is deleted.                                                                                            |
| 10  | Backfill clock         | A history message moved the thread's times to its own time                      | Times only move forward (`greatest`), so importing old history never drags a live thread's clock back.                                                                                                      |
| 11  | Disconnect             | The Page's broadcasts and posts stayed orphaned                                 | The schema cascades: they go with the Page. Inbox threads stay.                                                                                                                                             |
| 12  | Message lookup         | JSON path scan joined to conversations                                          | An expression index (`20261015090200_fb_message_dedup_idx.sql`).                                                                                                                                            |
| 13  | Send loop              | Driven by an open browser tab (25 per tick, 400 ms apart); closing it paused it | A worker job (`fb-broadcast`), 25 per batch about 50 ms apart; closing the page does not pause it.                                                                                                          |
| 14  | Counters               | Incremented per row                                                             | Recomputed from the recipient rows after each batch, so an interrupted batch cannot drift them.                                                                                                             |
| 15  | `{name}`               | The screen promises `{name}`; the sender only replaced `{{name}}`               | The sender replaces `{name}` too, so what the screen promises is what is sent.                                                                                                                              |
| 16  | Pause and retry        | `pause` set draft whatever the status; `retry` ran even while sending           | Pause acts only on a sending broadcast (the screen has no Pause button); retry while sending is a 409.                                                                                                      |
| 17  | Audience size          | Every thread inside the window                                                  | The newest 5000 per Page (a create takes the same most).                                                                                                                                                    |
| 18  | Page revoked mid-run   | The next browser tick found the Page not live and stopped                       | The next batch finds it flagged and fails the broadcast with the reason; a send refused with code 190 flags the Page.                                                                                       |
| 19  | Setup write answers    | A redirect back to the setup page with a flash                                  | `200 {message}` with the line the screen shows; a refusal is a 422 `FB_SETUP_REJECTED` (Meta's reason) or `FB_SETUP_UNSUPPORTED`. The screen reloads with `GET /facebook/setup`.                            |
| 20  | Read permission        | The same plan gate for reading and writing                                      | `fb.setup.manage` for both, and the response carries the Page picker, so a role that can set up Messenger needs no other key to use the screen.                                                             |
| 21  | Fallback Graph version | A system setting `fb_greeting_graph_version` (default v19.0)                    | Environment `FB_GREETING_GRAPH_VERSION` (default v19.0; empty disables the retry).                                                                                                                          |
| 22  | Audit                  | None                                                                            | Each successful change is written to the audit log against the Page (nothing is stored here, Meta holds the profile).                                                                                       |
| 23  | Making a post          | A form with an upload, a pasted-URL box and a schedule flag plus a local time   | `POST /facebook/posts` takes public addresses (`photoUrls`, `videoUrl`) and `scheduledAt` as an instant; the screen turns the user's local time into it. Uploading a file is blocked on the storage domain. |
| 24  | Meta refusing a post   | Back to the form with "Facebook rejected the post: ..." and the row left failed | 201 with the post: `status = failed` and `error`. The screen shows the same message.                                                                                                                        |
| 25  | Publish now            | The route accepted any status (the screen offered it for failed and draft only) | Only a draft or failed post: a published or scheduled one answers 409, because it would be posted twice.                                                                                                    |
| 26  | Post list order        | `ORDER BY scheduled_publish_time DESC` (MySQL puts empty times last)            | `DESC NULLS LAST`, so the order is the same.                                                                                                                                                                |
| 27  | Insights trend labels  | Dates formatted as "Oct 2" on the server                                        | `YYYY-MM-DD` in the viewer's time zone (`tz`); the screen formats them.                                                                                                                                     |
| 28  | Recent post fallback   | Read the picture from `media[0].url`, which never held a photo                  | Reads the first photo address of the post.                                                                                                                                                                  |

QUIRKS kept on purpose: a bad webhook signature is refused only when a secret is configured; `facebook_pages_limit` is never enforced; a
backfilled message still counts as unread; comment authors are not contacts.

## Not verified

- The Graph client has not made a real call (no Meta app here): it is covered by the e2e through a fake only.
- The signature check is covered by unit tests with a real HMAC; the end to end door is in the e2e that has not run yet.
- The platform switch `facebook_enabled` has no equivalent yet (the platform settings domain owns it); every organization with a Page is served.
