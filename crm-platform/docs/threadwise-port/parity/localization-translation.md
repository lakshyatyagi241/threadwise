## Reproduced quirks (deliberate)

- Saving an auto-reply does not translate it; the backfill and the lazy runtime path do (032 rule 6).
- Every non-matching inbound text goes to the provider in the fallback (034 rule 7), cached 24 hours.
- A failed target language is left out of a map; the rule still saves.
- A conversation language is pinned once, from the first inbound message, and never moves (036 rule 3).
- The 111-code target list includes codes some providers reject; those targets simply fail.
- Templates and forwards are never translated outbound; a text already in the customer's language is sent as typed.
- Stored translations are hidden, not deleted, when translation is switched off or the plan drops the feature (038).

## Not ported on purpose

- TW-I18N-006 beyond the refusal route (dead code in Reference).
- Per-language catalogs of Reference (`lang/*.json`): not copied; our catalogs are `messages/<locale>/<domain>.json` (inventory 012 port note).

## Blocked on other domains

- AUTOREPLY: the inbound lookup that calls `resolveInbound`, `pickContent` and `replyLanguage` (034), the rule editor that may call `translateForKeyword`, and `keyword_reply_logs.detected_language`.
- INBOX: ingest calling `translateInboundMessage`, the send worker calling `translateOutboundMessage` before the branding footer, the thread serializer calling `threadView` (036 to 038).
- AI agent and widget: adding `languageHint` to the system prompt (039).
- Shell and auth zones: mounting `LocaleSwitcher` (010).
- The shims `PgKeywordRuleStore` and `PgConversationMessageStore` read and write the auto-reply and inbox tables in this domain's zone; each is replaced by that domain's repository behind the same port.
