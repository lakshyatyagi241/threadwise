# Parity: add-ons, extensions and the module registry (ADD)

Evidence is automated (real Postgres, real Redis through the app harness): `apps/api/test/e2e/addons-extension-registry/addons.e2e.spec.ts` (9, packs, install, toggle, remove, verify),
`addons-modules.e2e.spec.ts` (21: engine connect and disconnect, one engine at a time and its teardown, in-place modules, navigation and plan fields of a module, install gates and audit,
the workspace catalogue), `test/integration/addons-extension-registry/addons-schema.spec.ts` (7: RLS, constraints, fulfilment) and `extension-tokens.spec.ts` (7),
`test/unit/addons-extension-registry/` (39: entitlement merge, manifest, zip and install, module gate, grant bullets), and `apps/web/src/features/addons-extension-registry/` (12: pack form
logic, messages, rail contributions). Screens were compared with the running Reference (`/admin/extensions`, `/admin/addons/create`) once, side by side with our own pages in a headless browser;
the rest of the comparison is from the Blade views (`admin/extensions/index`, `admin/addons/index`, `admin/addons/form`, `user/account/index` add-ons pane) and
`resources/js/charts/admin-extensions-index.js`.

## Deviations from Reference (all intended, need owner approval)

| Where                                          | Reference                                                              | Here                                                                                                                                    | Reason                                                                     |
| ---------------------------------------------- | ------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| Uploaded code                                  | PHP is loaded at boot                                               | files are tracked and gated, nothing a package ships is executed                                                                        | Node cannot hot-load arbitrary code safely; owner decision (port-map risk) |
| Disable an uploaded extension                  | flips a flag nothing reads                                          | the row is the one source of truth, `ModuleGateGuard` answers 404 when off                                                              | TW-ADD-007 QUIRK, defect                                                   |
| "Blocked" card for a deactivated native module | view blocks, server allows                                          | one predicate for both                                                                                                                  | TW-ADD-021 QUIRK                                                           |
| Slug of a package                              | unvalidated, steers extraction                                      | `^[a-z0-9_-]{1,64}$`, traversal and core paths refused, ZIP bounds                                                                      | security                                                                   |
| Purchase code                                  | any code, even empty, is accepted                                   | a code is required (`ADDONS_REQUIRE_PURCHASE_CODE`), never stored in clear or audited                                                   | licence model is INST's; the empty-code bypass is not ported               |
| Engine URL                                     | any host                                                            | private, loopback and link-local hosts refused unless `ADDONS_ALLOW_PRIVATE_ENGINE_URLS`                                                | SSRF                                                                       |
| Engine failure text                            | "<brand> not connected - <reason>." with the reason's own full stop | one full stop                                                                                                                           | defect (double stop)                                                       |
| Dormant module flag (TW-ADD-015)               | defined, never called                                               | applied inside the entitlement merge, as the inventory's port note asks                                                                 | the inventory's own acceptance criterion                                   |
| Add-on delete                                  | allowed, strips owners' grants                                      | refused while owned; take it off sale                                                                                                   | TW-ADD-030 QUIRK                                                           |
| Add-on limit merge                             | adds onto "0 means unlimited" and lowers it                         | an unlimited cap stays unlimited                                                                                                        | TW-ADD-031 QUIRK                                                           |
| Add-on audit                                   | no audit row for pack CRUD                                          | an audit event in the same transaction                                                                                                  | improvement the inventory allows                                           |
| Extension token (TW-ADD-034)                   | no expiry in practice, tokens left behind                           | always expires (default 30 days, at most a year, NOT NULL), issuing sweeps that user's expired ones, deleting a user deletes the tokens | defect                                                                     |
| Boot teardown (TW-ADD-022)                     | every web request checks                                            | one check at API start and after the native module is uninstalled; clears the flag only                                                 | the inventory's port note                                                  |
| Not-executed route files, `after`, `nav.user`  | read, unused                                                        | `after` and `nav.user` are accepted and ignored, as in Reference                                                                           | parity                                                                     |
