# Parity evidence: contacts, groups, tags and attributes (CON)

Reference 1.7.0 (running reference at `http://127.0.0.1:8000`, Docker) against ours (`apps/web` on :3001, `apps/api` on :3100), branch
`lakshya/contacts/contacts-port` at `dfcdceb` plus the fixes listed below. Run on 2026-10-02 by a Claude Code session with Playwright 1.60 in
its own browser. Covers TW-CON-001 to 049 (the screens and the contact, group, tag and attribute endpoints behind them). The public REST API
(TW-CON-056 to 064), webhooks (052), flow triggers (053) and the mobile and Node-bridge feeds (050) are other tracks and were not compared.

## How the comparison was made

- **Reference.** A workspace user (`user@threadwise.test`, workspace `Parity Workspace`, starter plan) that owns an empty workspace. Key flows were
  driven through the real screens (add with the default title, double click, edit prefill, bulk bar, import modal, group modal, 390 px). The
  matrix of validation, search, filter, import, export, group, attribute and phone cases was run from the same logged-in page against the same
  endpoints the screens call (JSON `fetch` for the writes, the server-rendered HTML for the list, parsed in the page). The reference runs on one
  PHP process shared with other agents (10 to 60 s per request), so cases were batched; the database was read with `SELECT` only.
- **Ours.** Our own login, the real screens for add, edit, delete, bulk, import, dedupe, groups, attributes, tags and the picker, plus the API
  through the web proxy for the matrix. A second, local test user with a read-only contacts role covered permission denied.
- **Every difference** is classed `same`, `intended` (owner-requested in [product-extensions.md](product-extensions.md) or a decision in the
  inventory's "Port decisions"), `defect, fixed` (our bug, fixed with a regression test), `defect, open`, `decision` (Reference behaviour that looks
  accidental or a choice the owner has to make) or `not verified`. Rows that say "from source" were read from the Laravel code and not run.
- **Test data** used the prefix `PARCON` on both sides and was removed again (see the end for what could not be).
- The harness of `threadwise-playwright-parity` assumes a Linux host (`setsid`, bash `parity.sh`); the scenarios were run with plain Playwright scripts
  instead. They and the raw results are kept outside git in `_work/parity/contacts/` (`scripts/`, `results/`, `shots/`). No twin spec was added
  to `apps/web/e2e`, so the stamp says what was and was not covered.
