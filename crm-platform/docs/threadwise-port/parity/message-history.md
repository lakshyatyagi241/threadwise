# Parity: Message History (`/message-history`, TW-CHAT-038 to -042)

What the screen does differently from Reference, and what was not compared. Rules and routes: [docs/api/chat-conversations.md](../../api/chat-conversations.md#message-history-message-history-tw-chat-039-to--042).
Wiring: [message-log.md](../wiring/message-log.md#message-history-screen-reference-message-history-tw-chat-039-to--042). Inventory: TW-CHAT-038 (the unified stream), 039 (page, filters, table, detail), 040
(cards, charts, top conversations), 041 (CSV export), 042 (archive button and dead hooks).

**Not compared against the running reference.** There is no signed-in reference session in this environment and no browser: behaviour here is from `MessageHistoryController`,
`UnifiedMessageStream`, the two Blade views and the inventory entries. Status of every row: `intended`, pending sign-off by the domain owner.

## Kept as in Reference

The header (crumb, title, range select, Export CSV), the five cards (total with the change against the last period, sent, received, failed with the failure percentage, average first response) with
Reference's definitions (`sent` is outbound that did not fail, `failPct` is failed over sent, the change is against the equal period before), the volume chart with Daily / Hourly / Weekly, the direction ring,
the filter bar (search, All / Sent / Received / Failed tabs with their counts, number select, type select), the table columns (When, Dir, Contact, Message, Type, Status, Open), the type pills and the six type-mix
buckets (template and audio count as plain text, as in Reference), the status dot and word, the open eye going to the broadcast, campaign or scheduled message and otherwise to the conversation, the detail
panel's content (direction, status, type, time, text, failure, message id, source, phone, language, created), top conversations (4), the empty state, and the CSV's formula guard. Times are shown in the
workspace's time zone (then the browser's).

## Intended differences

| #   | Reference                                                                                                                                                                       | Here                                                                                                                                                                                                                                                                                | Why                                                                    |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 1   | Six tables merged in PHP, newest 200 of each, page size clamped to 100: every card, chart and the table's total came from the newest 100 rows (TW-CHAT-040 quirk)               | One SQL feed; the cards, charts and tab counts are real counts of the whole window; the table loads by cursor                                                                                                                                                                       | (b) architecture; the inventory says the port must                     |
| 2   | Numbered pages: Prev, 1, 2, 3, Next, "Showing a-b of N"                                                                                                                         | **Load more** and "Showing n of total" (the total is the tab's count)                                                                                                                                                                                                               | (b) cursor pagination                                                  |
| 3   | Two copies of every Quick Send message (`legacy` "Direct send" and `inbox`), because `messages` and `inbox_messages` were two tables                                            | One message stream, so one row per message. There is no "Direct send" source                                                                                                                                                                                                        | (b) the two tables were folded into `messages`                         |
| 4   | The number (device) select was read and echoed but never applied                                                                                                                | A **Channel** select that filters messages. Broadcast, campaign and scheduled recipient rows name a device, not a channel, so a channel filter shows messages only                                                                                                                  | bug fix                                                                |
| 5   | A GET form for range / type / device / search plus an AJAX layer bound to missing ids: the Sent / Failed tabs and the bucket tabs reloaded with the default range and no search | One state in the address (range or dates, direction, type, source, status, channel, search, bucket, the open row). Back, reload and sharing work                                                                                                                                    | bug fix                                                                |
| 6   | An unknown `range` meant 7 days (no `range` meant 30)                                                                                                                           | An unknown `range` means 30 days                                                                                                                                                                                                                                                    | bug fix                                                                |
| 7   | Scheduled rows: one row per scheduled message, "phone" was the sender's number; broadcast rows had no number or name; campaign rows had the recipient                           | One row per recipient for broadcasts, campaigns and scheduled messages, each with its own status, the contact's name and the recipient's number                                                                                                                                     | bug fix; the recipient is what History is for                          |
| 8   | Auto-reply rows came from the fire log (status `fired`), whether or not a message went out                                                                                      | An auto-reply is a message (Type "Auto-reply"), with its real delivery status                                                                                                                                                                                                       | (b) the reply is stored as a message now                               |
| 9   | Reference printed full numbers although its `mask_customer_numbers` setting defaulted ON (it stored the setting and nothing read it)                                            | A number is whole only for a contact the caller may read (`record.contacts.read`, by scope); else the last 4 digits. Broadcast / campaign / scheduled recipient rows only for scope `all`        | (c) hardening; the repo's record-scope model                           |
| 12  | The detail panel was filled from the row's truncated `data-*` attributes; its follow-up `GET /message-history/{id}` had no route                                                | The drawer loads the row by id: whole text, sender, channel, template, cost, the failure in plain words (the WhatsApp failure map), and every delivery step, read from the archive for a message older than 90 days                                                                 | bug fix; the inventory's port note                                     |
| 13  | Export: a synchronous stream of the chosen range only (columns: id, source, when, direction, phone, contact, status, type, body)                                                | Asynchronous through the delivery log's export queue, with every filter of the screen; emailed and downloaded from the page for 7 days. Needs `inbox.logs.export` and scope `all` | (b) 10,000-row cap and request timeouts; (c) the file has every number |

The delivery log is archived by its own daily sweep                                                                                                                                                                                                      | dead code                                                              |
| 15  | "Top conversations" showed `lastAt` as UTC epoch time without the display zone                                                                                                  | Shown in the display zone                                                                                                                                                                                                                                                           | bug fix                                                                |

## Not built here, recorded

- Pickers for the template, campaign, broadcast and scheduled-message filters. The API takes them and the screen honours them from the address (shown as removable chips); the campaign, broadcast and template
  screens do not link to a filtered history yet.
- Recipient rows of a campaign mirrored into a thread before this change have no `meta.campaign_id`: if the mirror carried a real WhatsApp id (not the `campaign:` fallback) that old bubble is listed next to its
  recipient row. New mirrors carry the key.

## Not verified

No browser run (no pixel or keyboard comparison with Reference, no screenshot), no run against a live WhatsApp account (receipts and failure codes come from fixtures and the simulator), the "ready" email was not
read in a mail client, the 21 translations were written by translators working from the English text and were not read by a native speaker of each language, and the screen was not tried on a phone.
