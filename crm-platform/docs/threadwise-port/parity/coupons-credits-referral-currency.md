## Intended differences (owner approval pending)

Cursor pagination; UTC buckets; daily series capped at 366 points; money as hundredths + currency code on every surface; ledger description carries no referee identity; payout stamped by a locked, idempotent consumer; referee/referrer are users within workspaces, rewards credit the referrer's workspace wallet; lifetime count is true; status paid/pending.

## Playwright twin against the running Reference (2026-10-06)

Three twin specs run the same scenarios on Reference and on our build and compare behaviour, never wording: `apps/web/e2e/coupons-credits-referral-currency/parity/TW-CPN-coupons.twin.mjs` (TW-CPN-001..005), `TW-CPN-currencies.twin.mjs` (TW-CPN-018..024) and `TW-CPN-affiliate.twin.mjs` (TW-CPN-029..037); shared helpers in `cpn-shared.mjs`. Our side ran against a scratch database (`crm_cpn_parity`) with the web app in dev mode, our API and a worker (needed for referral attribution); our admin screens were driven as a platform operator that exists only in that database. Referrals were seeded by normal use on both sides (a referrer registers, referees register with the referrer's code). Everything the runs created carried the run prefix and was removed by prefix; Reference's user and workspace trash was purged for the tagged referrer only.

Result after one fix round: coupons 0 defects (1,606 same, 198 intended), currencies 0 defects (1,163 same, 183 intended), affiliate 0 defects (199 same, 22 intended). Remaining `review` items were looked at and decided (below).

### Decided review items (structure differs, not a defect)

- Money fields are text inputs with a decimal keypad on ours and number inputs on Reference (exact decimals, our own messages).
- Currency code box holds three characters (ISO), see above.
- The console shell has more buttons and landmarks (collapsible menu, top bar); list pages hold twelve rows on ours against three on the reference, which multiplies row buttons.
- The affiliate account tab and the history page are one screen on ours (inventory TW-CPN-037 port note), with an accessible data table for the chart.

### Intended differences recorded by the twin run (owner approval pending for the first five)

1. Currency code limited to three letters (ISO 4217).
2. A taken code or currency code answers 409 with a stable code, not 422.
3. Money text refused when it has more decimals than the column (coupons four, rates six) and plain-decimal only.
4. Direct sign-up API calls with a malformed referral value are refused (the screens clean it first).
5. The operator console is a separate sign-in (customer session gets the sign-in screen and 401).
6. Literal search (no `%` / `_` wildcards), concurrent-edit conflicts, code and rate immutability rules, NUL refusal, emoji kept, ASCII-and-Unicode upper-casing, CSV BOM and formula safety, referral code cleaning, unpaid status wording.
