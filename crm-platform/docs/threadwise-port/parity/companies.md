Companion files: [tasks.md](tasks.md), [deals-pipelines.md](deals-pipelines.md).

## How this was run, and its limits (read this first)

- **The Playwright twin run was NOT done.** It needs a running Reference reference and a running copy of our stack, and starting servers (and
  migrating the dev database) was out of bounds for this change. Nothing below was observed in a browser, on either side.
- **Reference side:** read from the licensed source only (controller, model, views, JS, migration, routes). No behaviour here was
  re-checked on the running reference, so every "Reference" cell is a source reading, and the inventory says so where it matters.
- **Our side:** the API is covered by 46 end-to-end tests over HTTP against a real Postgres (testcontainers) and 21 schema tests against the
  restricted application role; the web by pure-logic tests, 18 server-render tests of the components (strings, escaping, states, permissions)
  and the English/Arabic message parity test. `next dev` was not started, so layout, spacing, dark mode, RTL mirroring, 390 px, keyboard
  behaviour, focus handling of the dialogs, toasts and the navigation after create/delete are **not verified**.
- Legend: **same** = equivalent behaviour per the source and a test; **intended** = differs on purpose (a `D-nn` of
  [the inventory](../inventory/companies.md#port-decisions) or an owner extension, with the reason); **not verified** = needs the
  twin run.

## What is not verified

- BL-034 (rows C37 to C46): nothing was compared on the running Reference or in a browser. The picker, the tasks card, the properties screen and the error wording were checked by pure-logic tests, server-render component tests (strings, escaping, states), message tests in 21 languages and API end-to-end tests over HTTP against a real Postgres. Keyboard behaviour of the combobox, focus handling, the drag reorder of properties, layout, RTL mirroring, 390 px and dark mode are not viewed (BL-195). The 20 non-English strings were written to match the existing contact wording of each language and have had no native review.

- Everything in the browser (C36 and every "same (code)" / "same (SSR)" row): the twin run in `threadwise-playwright-parity` must be done with
  a running reference and a running stack. Nothing has been compared pixel for pixel or flow for flow.
- The migration was applied to a fresh database only (testcontainers and a throwaway container); the backfill of rows that predate the
  new CHECKs (trim, truncate, name filled from the website) is written but not exercised against a database that already has companies.
- The Agent preset's new grants on a running environment appear when the 10-minute permission cache expires.
