# Target map: what crm-platform already has, and the rules new work must obey

Snapshot of `main` @ `85f6513` (merge of PR #11, 2026-09-28), read on 2026-09-30. Read-only research: I read the docs,
skills and every source file listed in the brief, and ran nothing (no Postgres, Redis, Docker, test runs or builds). Anything I
could only infer, or that only a doc claims, is stated as such or listed in section 8. Everything else was read in code.
Paths are repo-relative. Untracked sibling files under `docs/wadesk-port/` and the five `wadesk-*` skills were being written by
other people while I worked; they are outside this map.

**One-paragraph verdict.** The target is a solid, unusually disciplined _foundation plus one vertical slice_: tenancy/RLS,
RBAC, outbox, audit, idempotency, cursor pagination, problem+json, custom-field registry, and a complete Contacts slice
(contacts, tags, saved views, notes, files-metadata, activities, meetings, field history) plus staff admin, partner portal and
public API. Everything WaDesk is _about_ (channels, inbox, messages, broadcast, wallet, flows, AI, storefront, file storage,
notifications, plans, super-admin) has **no code and no tables**; five modules are README-only. The outbox has **no consumers**,
BullMQ has **no producers or processors**, realtime has **no emitters**, and there is **no frontend at all**. All 87 HTTP routes
are in section 2; the 31 tables (30 tenant + 1 global) are in section 2.12.

**Outbox drain** (`apps/api/src/workers/outbox-drain.service.ts`): every 2s, privileged tx, `FOR UPDATE SKIP LOCKED`, 200/batch,
backoff `min(2^attempts,900)`s, dead after 8. `dispatch()` only writes a debug log, so every event is marked `done` with **zero
subscribers**. Runbook: `docs/runbooks/outbox-backlog.md`.

**Realtime** (`apps/api/src/realtime/`, rebuilt 2026-10 for the inbox, see `docs/api/realtime.md`): namespace `/realtime`; the browser connects with a
one-time ticket (`POST /v2/realtime/ticket`, minted through the web proxy) and the gateway also still takes `auth.token`. Every socket joins `org` and
`user`; `conv:` and `inbox:` rooms only through `room:join`, authorised by the same visibility rule as the REST read. Publishing is
`RealtimeEmitter` (`@socket.io/redis-emitter`, per-room sequence numbers), imported by the HTTP app AND `worker.ts` through `RealtimeEmitterModule`; who hears
an event is decided by `AudienceResolver`. Nothing publishes yet except the tests: the inbox phases are the first callers.

**Storage / email / providers.** `S3_*` and `SMTP_*` env keys, MinIO buckets `crm-media|crm-documents|crm-exports` and Mailpit exist in
`docker-compose.yml`; there is no S3 client, no uploader, no mailer. Providers (`apps/api/src/infra/providers/`): WhatsApp
port + `MetaCloudProvider` (webhook signature verify + parse are real; `sendTemplate`/`sendText` **throw "not implemented"**);
Easebuzz payment **port only** (`payments/easebuzz.port.ts`, no adapter, not bound in `providers.module.ts`).

**Tenancy mechanics** (`apps/api/src/infra/db/database.service.ts`, `packages/db/src/tenant.ts`): `tx()` / `txReplica()` read org+user from the
AsyncLocalStorage `RequestContext`; `txAs({orgId,userId})` for jobs; `privileged()` sets `app.privileged='on'`. All open a transaction
and `set_config('app.org_id', …, true)`. App connects as `crm_app_user` (NOSUPERUSER NOBYPASSRLS; group role `crm_app`), migrations as
owner `crm`. `int8` parser converts bigint to `number`; `numeric` stays string. Replica falls back to primary when
`DATABASE_REPLICA_URL` is unset/equal; production boot refuses to start without it (`config/env.schema.ts`).

`JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET` (>=32 chars), `CREDENTIALS_ENCRYPTION_KEY` (base64 32 bytes), **`CLERK_SECRET_KEY`** (required even
if you never use Clerk). Optional/defaulted: `PORT`, `APP_URL`, `LOG_LEVEL`, `CORS_ORIGINS`, `DATABASE_REPLICA_URL` (required in prod),

DB column `rate_limit_per_minute` is what the guard reads), `SENTRY_*`.

**Deploy.** `docker-compose.yml` = dev infra (postgres, optional `replica` profile, redis, minio + bucket init, mailpit). `docker-compose.prod.yml` =
api, worker, postgres (`wal_level=replica`), redis; **no caddy, no S3, no web** despite the single-VM deploy plan. CI (`.github/workflows/ci.yml`): static (format,
lint, typecheck, arch:check), test (migrate from scratch, `db:status`, unit, testcontainers integration), docker build. No e2e job, no web job.

### 2.1 Kernel, infra, common (shared services every module uses)

- `OutboxService.emit(tx, {aggregateModule, aggregateId:number, eventType, payload, orgId?})` (`kernel/outbox/outbox.service.ts`): inserts into `event_outbox`, adds `_meta{requestId,actorType,actorId}`; `orgId` override exists, but `RequestContextStore.peek()` is used for meta so it works without context only if `orgId` is passed.
- `AuditService.record(tx, {module, recordId:number, action:'insert'|'update'|'delete'|'merge'|'login'|'export', delta?})` (`kernel/audit/audit.service.ts`): always calls `RequestContextStore.require()` (**no orgId override**), so it cannot run in a worker without a manually-run context. `diff(prev,next)` keeps only changed keys present in `next`. `listByRecord()` powers field history. `audit_log.ip` exists but is never written.
- `RbacService` (`kernel/rbac/rbac.service.ts`): `grantsForUser`, `can(grants,key)` (denied => scope `own`), `rolesVersion()` and `bumpRolesVersion()` both use `db.privileged()` — **reachable from HTTP** (every permission-cache miss via `PermissionsGuard`; roles/users services call the bump, outside the caller's tx). Neither is one of the four sanctioned uses.
- `DisplayIdService.next(tx, orgId, moduleKey, prefix)` -> `CON-00001`, batches of 100 held in process memory, gaps by design; backed by `sequence_counters`. Only contacts use it.
- `CryptoService` (`common/crypto/crypto.service.ts`): AES-256-GCM `v1:iv:tag:ct`. Used only by `ApiKeyGuard`; channel credentials are documented to use it but no channel table exists.
- `RequestContextStore` (`common/context/request-context.ts`): `require()`/`peek()`; context starts `orgId 0, actorType 'system'`, guards fill it. **Workers and webhooks must build/enter a context themselves** (`RequestContextStore.run`) before calling any service that uses `db.tx()` or `audit.record()`.
- `AppError` statics: `notFound`, `forbidden`, `unauthenticated`, `rowVersionConflict`, `validation`; raw `new AppError(code,msg,status)` for others (`common/errors/app-error.ts`). `ProblemExceptionFilter` = the only error formatter.
- `IdempotencyInterceptor`: Redis `idem:{orgId}:{key}` SET NX 24h, replay stored body, 409 while in flight. **Header is optional** (no key => handler just runs); the decorator's JSDoc saying "Requires" is wrong.
- `buildPage()` / `encodeCursor()` (`common/pagination/cursor.ts`): cursor = base64url `iso|id` over `(created_at,id)`.
- Decorators (`common/decorators/index.ts`): `@Public`, `@RequirePermission(...keys)` (OR), `@GrantedScope(key)` (defaults to `'own'` if grants absent), `@Idempotent`, `@ActorKinds`, `@CurrentActor`, `@ReadReplica` (defined, **never used**).

**Roles and grants.** `roles(system_key, is_locked)`, `user_roles`, `role_grants(effect allow|deny, record_scope all|team|own)`. Seed (`packages/db/src/cli/seed.ts`) creates **Admin** (locked, every key at seed time, scope `all`) and **Counsellor** (5 grants: contacts read/update `own`, contacts create `all`, inbox read/reply `own`) per org; the `manager|agent|readonly` system keys mentioned in the schema comment are not seeded.
**Merge** (`RbacService.loadGrants`): deny is absorbing across roles; among allows the widest scope wins (`all>team>own`). `can()` on a denied/missing key returns scope `own`. Cache key `rbac:{org}:v{roles_version}:u{user}` TTL 600s plus `rbac:version:{org}` TTL 600s; `bumpRolesVersion(orgId)` after any role/user-role change (roles/users services already do).
**Scope semantics** are applied **only** for contacts (`ContactsRepository.scopeCondition` for list/select-data; `assertContactScope` for single/bulk/sub-resources). `team` = owner shares a `team_members` team with the caller; there is no API to create teams. Every other `supports_scope=true` key is a promise with no code behind it (the `rbac-permission` skill calls this out as worse than no permission).
**Non-staff actors** carry no grants; `PermissionsGuard` throws 403 for non-`user` actors on any `@RequirePermission` route. A route with no `@RequirePermission` only needs authentication (`GET /v2/users/me`).
**How to add a key (the working recipe):**

1. New migration (`pnpm db:new add_x_permissions`, next is 0020) that `INSERT INTO permission_defs … ON CONFLICT DO UPDATE`. Never edit 0008 (checksummed).
2. Decorate routes with a **string literal** `@RequirePermission('record.x.read')` — a permission-key scan greps literals only and cannot see keys built at runtime (`propertyPermissionKey()` is the known exception, verified by hand).
3. For scope-capable keys, take `@GrantedScope('record.x.read')` and apply it in the repository; for sub-resources reuse the parent's key plus a shared `assert…Scope` like `contact-scope.ts`.
4. **Granting to existing tenants is not automatic.** `role_grants` has a `BEFORE INSERT/UPDATE/DELETE` trigger that rejects changes on a `is_locked` role (Admin). Migrations 0011/0015/0018 only register keys; they do **not** grant them, so already-seeded orgs' Admin roles lack every key added after 0008 until someone unlocks, inserts and relocks (the seed does unlock -> insert -> lock). A migration that wants Admin to have a new key must do that dance explicitly, then `bumpRolesVersion`.
5. Add the key to the seed grants for non-Admin roles if needed, and to `docs/api-testing.md` for the route.
   **Per-moduleKey keys.** For a generic registry route (like field metadata) copy `field-metadata-permission.ts`: coarse OR gate on the route, precise check in the service.

### 7.2 Design mismatches to resolve before mapping hundreds of features

- **Tenant model:** the target is a flat `organizations` tenant; WaDesk (per the inventory files: workspaces, plans, super-admin, addons, BSP/billing engine) needs an operator layer above it that the current design excludes.
- **Roles model:** grants are keys x effect x `all|team|own`; WaDesk's permission model must be re-expressed as keys (a "permission-tree" shape is a known open item in phase 2).
- **Inventory/gating documents describe a different frontend.** `docs/api-inventory.md` and `docs/phase-plan.md` list a 28-page, ~582-API audit with legacy RPC names (Pinnacle, sub-accounts, Zoho…); WaDesk features have no rows there. The phase gate and Swagger-exposure rule reference those phases.
- **Channels:** the port models an API-key/webhook BSP (`senderId`, `accessToken`); no notion of QR pairing/session state, per-channel health, or multiple connected numbers (`channels` table never designed in code).
- **Realtime from background work:** the documented flow (outbox -> realtime emit) crosses processes but the gateway is API-only.
- **Custom fields are inert:** contacts accept any `customFields` JSON; `is_required`, `is_unique`, `is_masked`, `is_read_only`, `field_type`, options and dependencies are stored but never enforced on write or applied on read (`grep` finds no consumer outside `crm/fields`). The field-registry design says validation is application-layer; that layer does not exist.

### 7.3 Doc/code drift and defects found while reading (verify before relying)

1. **Auth vs the identity design.** Staff login by Clerk (commit `34e89d5`, migration 0009) contradicts the identity-pool design ("own JWT auth"; Clerk was listed among rejected alternatives) and was never agreed. `CLERK_SECRET_KEY` is required at boot for API and worker.
2. **Clerk exchange trust:** `AuthService.loginViaClerk` takes `orgSlug` from the request body and, for any valid Clerk identity, links by email or **inserts a `users` row in that org** and issues tokens; it never checks `users.status` (deactivated users can still sign in via Clerk; password login does check). New rows have no roles, so they see only unguarded routes, but this is cross-tenant self-enrolment.
3. **Refresh** is stateless and does not re-check user/agent status; access-token verification never hits the DB.
4. **Docs vs seed:** README/runbooks/api-testing named a seeded org that `seed.ts` does not create (now corrected to the real seed); `packages/db/src/cli/seed.ts` seeds orgs `Admin` and `test_tenent`, a personal `@geta.ai` admin email per org, **no staff password**, agent `agent@Admin.test` / `Passw0rd!`. `README.md`, `packages/db/README.md` (lists only 0001-0008), `docs/db/README.md` are stale on this and on the migration list.
5. **Version drift:** live API is `/v2` (`main.ts` default `'2'`); CONTRIBUTING, skills (`frontend-api-call`) and `emit-openapi.ts` say `/v1`. `apps/api/src/tools/emit-openapi.ts` claims "CI fails if the committed spec is stale"; no CI step runs it and the file is gitignored.
6. **`docs/api-testing.md` "Known gap: contact sub-resources don't apply record scope"** is stale: notes/files/activities/meetings/tags all call `assertContactScope` now (commit `c0cdc3b`); bulk/select-data were fixed after.
7. **Audit/outbox holes (rule 6):** no audit/outbox on field options, dependencies, any reorder, tag attach/detach, favorites; partner `submitLead` is two transactions (contact committed before mapping/attribution); `RbacService.rolesVersion` and `bumpRolesVersion` run separate privileged transactions from HTTP paths (the bump happens before the caller's tx commits); no `login` audit rows.
8. **Read-your-own-write from the replica:** `PartnerService.submitLead` reads back via `txReplica`; `PublicApiService.submitLead` computes `created` from a replica read. Both contradict the rule written on `txReplica`.
9. **Identity graph is write-once:** `ContactsService.update` adds new email/phone identities but never removes old ones, and `ON CONFLICT DO NOTHING` silently skips an identity owned by another contact; public-API phone is not E.164-normalised before becoming an identity value.
10. **Saved views:** `contact_views.filter` is never applied; `GET /v2/contacts` supports only `q`, `ownerId`, `lifecycleStage`, `includeArchived`, and `created_at` ordering.
11. **`ContactsService` assumes grants:** `getByUuid/update/remove/bulk*/sub-resource` services call `rbac.can(ctx.grants!, …)`; `ctx.grants` is only set by `PermissionsGuard` on `@RequirePermission` routes, so calling these from a worker, bot or webhook throws.
12. **Idempotency doc:** decorator comment says "Requires an Idempotency-Key"; implementation treats it as optional. `@ReadReplica`, `WORKER_MODE`, Sentry, `PUBLIC_API_RATE_LIMIT_PER_MINUTE` env are dead.
13. **Test/CI claims:** CONTRIBUTING lists E2E tests; none exist. `rls.spec.ts` asserts RLS flags on 6 tables and behaviour on 2 (`contacts`, `partner_agent_leads`), none of the 14 tables added in 0010/0014/0017. `db:status --verify` (mentioned in `packages/db/src/schema/index.ts`) does not exist.

### 7.4 Traps for the first porting PRs

- Register any new module in `AppModule.imports` (currently a comment placeholder lists Inbox/Broadcast/Billing/Exams), add its Swagger tag in `main.ts` only when gate criteria are met, and if the worker needs its services add the module to `WorkerModule` **and** establish a `RequestContext` per job.
- `OutboxService.emit` takes a bigint `aggregateId` and `AuditService.record` a bigint `recordId`; `AuditService.record` cannot run without an ambient context.
- Enum additions: `ALTER TYPE … ADD VALUE` needs `-- @no-transaction`, is append-only, and must be mirrored in `contracts/common/enums.ts`.
- `contacts.create` returns the _existing_ contact on an identity match, so it is not an upsert for imports; imports need their own path (and `contacts.legacy_id` exists for reconciliation only).
- The partition list is read from the catalog (`pg_partitioned_table`); `DEFAULT` partitions come from each migration; the `_default` alert is a log warning from `defaultPartitionCounts()` at the end of each pass. Partitions are created by the `SECURITY DEFINER` `ensure_monthly_partition()`; `crm_app_user` cannot create one directly.
- `privileged()` has 7 call sites: sanctioned = `AuthService.resolveOrgId`, `ApiKeyGuard.lookupKey`, `OutboxDrainService`, `PartitionMaintenanceService` (x3); **unsanctioned but reachable from HTTP** = `RbacService.rolesVersion`, `RbacService.bumpRolesVersion`. A new site needs an argument (and a tenancy-design amendment), not a copy.
- Decisions to settle: platform-operator pool; onboarding/privileged use; Clerk vs own auth; unofficial/QR WhatsApp provider; file storage + upload path; worker-to-realtime bridge; plan/limit gating; i18n; mandatory idempotency; Tier-3 `records` for module-like WaDesk objects.
