# Parity: workspaces-teams-tenancy (WSP), PR 1: members and teams

Scope of this file: WD-WSP-015 to 022, 046 and the member part of 047 (backend). Screens (apps/web) are a separate slice and
are not covered here. The running reference was NOT driven side by side in this slice and no browser was used: every
"looks the same" claim for the screens is unverified (see Not verified).

Evidence is automated (real Postgres, real Redis, the real Nest app): `apps/api/test/e2e/workspaces-teams-tenancy/members-teams.e2e.spec.ts`
(one block per WD-WSP id, one named test per acceptance criterion), `test/integration/workspaces-teams-tenancy/members-teams-schema.spec.ts`
(migration over a pre-existing installation, role presets, RLS, constraints, repositories as the restricted role) and
`test/unit/workspaces-teams-tenancy/member-rules.spec.ts` (the rank rules).

## Status

Built (API + migration + tests): WD-WSP-015, 016, 017, 018, 019, 020 (role model: tiers, presets, grant and act-on rules), 021
(as accept-by-link), 022, 046 (rank guard, applied to the member actions). Not in this PR: WD-WSP-001..014 and 023..045, the

## WD-WSP-046 and the admin staff-user screens

046's original home is the platform admin's user screens (create, edit, suspend, import accounts across workspaces), which belong to
WD-WSP-038..045 and are not built here. This PR applies the same rule (actor rank must be at least the target's, only the top rank
hands out the top role) to every member action. The existing staff-user module (`apps/api/src/modules/admin/users`, route
`PATCH /v2/users/:id` with `roleIds`) still has **no rank check**: a caller with `admin.user.manage` can assign any role, including
Admin, to anyone. That path needs the same guard before it is exposed to non-admin roles (recorded as a follow-up, not changed here
because it is outside this domain's zone).

## Blocked / not built

- Ownership transfer (explicit action) and "leave workspace" are not built; WaDesk has neither.
- Teammates' avatars (`avatarUrl` is null): the account domain serves only the caller's own picture.
- Realtime presence: values are whatever the inbox stored in `agent_statuses`; no feed exists yet (TIB/TCHAT).
- Invitation mail goes out right after the commit rather than through an outbox consumer: the mail adapter lives in AUTH and there is
  no worker consumer for it yet; a crash between commit and send leaves a pending member whose link can be sent again with "resend".
