# Parity evidence: deals and pipelines (WD-DEAL-001 .. 047)

WaDesk 1.7.0 (Docker reference, workspace user `user@wadesk.test`, workspace "Parity Workspace", UTC, no currency set so it shows
USD) against our build at branch `lakshya/contacts/contacts-port` (working tree on top of `dfcdceb`), run on 2026-10-02 by a
Playwright + HTTP pass on both apps. Scope: board and list, create, edit, delete, stage move (drag and menu), won, lost, reopen,
the timeline and its tasks, contact link, reports, filters, boundaries, empty states, double submit, viewer permissions, currency,
RTL, 390 px, script in a title. Companion file for tasks: [tasks.md](tasks.md).

Deals, the pipeline and stage editor, the lost-reason catalogue and per-column paging are an **owner-requested extension**
(product-extensions.md, item 6); WaDesk has no editor and a single page. Differences that settle a "Differences to decide" row cite
the `D-nn` of [the inventory](../inventory/deals-pipelines.md#port-decisions).

## How this was run, and its limits

- Reference side: UI actions in Chromium for what a person does (board, new-deal modal, drawer, inline edit, Mark Lost, reports), and
  in-page `fetch` with the page's CSRF token for the boundary cases, then read-only `SELECT`s on the reference database to see what
  was stored. The reference answers about one request a minute (single-threaded `php artisan serve` shared with other sessions), so
  its matrix is narrower than the one run on our side.
- Our side: the same inputs through the web app (Playwright) and the API (`/v2/deals`, `/v2/pipelines`), plus a second user with a
  read-only role (viewer) and the seeded Agent (own scope).
- The reference workspace has no subscription package, so every feature flag defaults to on there: **the plan gate cannot be
  reproduced on the reference**. On our side `PLAN_FEATURE_LOCKED` is covered by the e2e suite and was exercised in the browser
  with an intercepted response.
- The worker was not running, so the deal reminders and notifications are not part of this run (they are follow-ups in the
  inventory anyway).

## Not verifiable here

- The plan gate on the reference (no package defined) and the real plan lock beyond the intercepted response.
- RTL on the reference, the reference's inbox, flow, order and API consumers, reminders and notifications.
- Filter behaviour on the reference (each try is a page reload at about a minute per request).

## Decisions for the owner

1. Board KPI strip: WaDesk's fifth tile ("Open deals") repeats the first one's count; ours has four. Keep four or add the tile (D05).
2. The contact picker in the New deal form (D10) is not in WaDesk's modal; the API already takes `contactId` on create. Keep or remove.
3. The reference's auto-create-deal-from-orders setting (D40) is not built; it needs the orders domain.
4. The development stand-in in `mock-server.ts` (D50), here and in the tasks feature: move it under `test/` or keep it.
5. The "?" avatar on an unowned card (D04) replaces WaDesk's "contact initials" quirk: keep.
