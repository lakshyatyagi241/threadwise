# Parity evidence: flow builder editor (FLB-014..027, node inspectors 030..067)

WaDesk 1.7.0 reference (http://127.0.0.1:8000) vs this branch. The flows LIST screens (WD-FLB-001..013) are in [flow-builder-editor-list.md](flow-builder-editor-list.md).

## Evidence

Twin harness `wadesk-playwright-parity`, spec `apps/web/e2e/flow-builder-editor/parity/WD-FLB-editor.twin.mjs` (180 scenarios), depth `full`, against the live
reference and this branch (demo workspace made by `parity/prepare-org.mjs`). Final state after three rounds: **same 1489, intended 98, defects 1 (open, blocked),
review 2 (decided: ignore)**. Every flow the run created is named `zz-flb-ed-...` and was deleted (checked on both sides afterwards).

What is covered, with real mouse drags where the UI allows it: palette content, order, count, groups, tip and search (label, description, group, case, padding,
no match) for a chat and a call flow; drag from the palette, wiring (output to input, release on a card, self connection, identical edge, fan-out, Escape),
edge popup, node action bar (pin START, edit, duplicate with Ctrl+D, delete), singleton Trigger, double-click add at the centre, undo / redo chords and the
60-entry history, zoom buttons and limits, Ctrl+wheel, wheel and drag pan, minimap, option removal renumbering ports; the inspector of every node type of the
chat palette (35) and the call palette (14): labels, control kinds, defaults, option lists, limits, every select option and the fields it shows, plus the
repeatable rows limits and every Trigger kind; the pre-save popup (missing connections, outline, selection, reset, "and N more", empty canvas, no Trigger,
Publish with an invalid graph); new-flow save modal, toast, URL, pill, second save, update + rename + reload, failed save, keyword over 255; publish of a
never-saved graph, edit while published, publish with unsaved edits, unpublish, pause; test runner transcript (hint, keyword start, ask, merge tags,
buttons, condition, delay, unwired port, empty canvas, Webhook SSRF block); AI generator modal states; XSS in node text and flow name; 390 px builder; API
save matrix (41 cases: name, category, type, graph shapes, caps, trigger keywords), ownership, unauthenticated access, publish / unpublish, webhook test
endpoint (20 destinations + method / header / body / vars), media upload errors (13), AI generate errors (10), builder reference data, export and import
round trip including malformed files and both exporters' file formats.

## Fixed during this run (found as defects, now same)

- Palette search: the query is no longer trimmed (QUIRK: a padded query matches nothing), like the reference.
- Card previews: only the message text (140) and media caption (80) end in an ellipsis when cut; every other preview is a plain cut.
- Webhook test endpoint: a blank `url` is a 422 (the reference validates it as required).
- New-flow name modal and the AI prompt box no longer carry a `maxlength` (the reference lets you type and answers 422 past the limit).
- The app shell (sidebar, header, banners) no longer sits in the builder's Tab order or accessibility tree; the reference page has no shell.

## Decisions (intended, each with its reason in the spec `intended[]`)

- Server caps (500 nodes, 2000 edges, JSON body size), node / variable shape validation, boot normalisation on save (one START, no edge to a missing node):
  WD-FLB-028 / 019 port notes; WaDesk trusts any array and normalises when the builder opens.
- Publish of a never-saved flow creates one row (WaDesk creates two, WD-FLB-022 rule 1); a rejected save stores nothing (WD-FLB-019 port notes, WaDesk stores then errors).
- Every declared output port is drawn (WD-FLB-017 rule 1), Hang up is terminal (WaDesk draws a dead output dot).
- WaDesk shows "Loading ..." for ever for an empty list (templates, forms, services, groups) and for Google pickers when Google is off; ours shows the empty
  picker, or a not-connected note with an id / link field.
- WaDesk's middleware stores empty strings as null in node data; ours stores the empty string (the runtime reads both as unset).
- Web app serves a page shell for an anonymous visitor and redirects on the client (no content served); the Next.js dev indicator is the one Tab stop without a ring.
- Literal backslash-n in two WaDesk placeholders is not reproduced.

## Open

- **Chatbot node, "Create new AI agent"** (blocked): WaDesk opens an inline create-agent dialog; ours shows the button disabled with a "Refresh list" link
  because creating AI agents belongs to the team-inbox AI-agents domain, which has no API yet. Unblocks when that domain ships create-agent.

## Not compared

- Channel palettes other than WhatsApp and call (Instagram, Facebook, TikTok, Telegram, LINE, WeChat, Viber, Email): they need a connected channel account on both sides;
  covered by the contract unit tests. The Trigger-without-sender check likewise needs a connected number.
- A successful media upload and a successful AI generation (object storage and a provider key are not available); the 50 MB limit (the local reference PHP caps
  bodies at 8 MB, so it answers 200 with a warning); a live webhook round trip to a public host.
- The other side's real export file: both exporters' formats are compared field by field, and the import of each format is run on both sides from fixtures written to match them.
- Rendering of the shared cookie banner at 390 px (app shell, not this domain).
