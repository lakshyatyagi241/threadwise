## Interop and cross-browser evidence

- **TOTP:** an independent from-scratch RFC 6238 implementation (checked against the RFC's own vectors) generated the codes the API accepted at enrolment and sign-in; a replayed code was refused. The enrolment URI has the Google Authenticator key-URI shape (`otpauth://totp/Issuer:account`, SHA1, 6 digits, 30 s, base32 secret of 160 bits).
- **Browsers:** the same scripted flow (wrong password, sign-in, httpOnly SameSite cookies, account security page, reload, sign-out, sign-up page, Arabic RTL, no page errors) passes in Firefox 150 and Chromium 148.
- **reCAPTCHA:** see the table above.

### Corrections to the inventory (verified in the reference source or in the running product)

- 001: the live login form HAS a show/hide eye on the password; `?logout=1` is never produced by WaDesk; "30 days" is only a label (the default lifetime is far longer); non-remembered sessions last 7 days.

### Status of the twin run

Run on 2026-10-02 for the guest pages only (`apps/web/e2e/auth-registration-security/parity/WD-AUTH-001.twin.mjs`: sign-in, sign-up, forgot password; page probes, nothing submitted): 126 checks the same on both apps (load noise, accessibility, degraded states, timing, structure counts aside), 0 real defects. The 3 "minor" keyboard findings are the Next.js development overlay, which is not in a production build. The structure differences (extra form and buttons) are the intended ones: workspace field (row 1/2), language and theme switches (row 27), cookie banner (row 28). The responsive probe is not valid for public pages: the harness opens its extra viewports with a session, so its WaDesk side compared the admin dashboard with our sign-up page. Disclosure: for that probe the harness signed in to the local WaDesk with the default test account built into the skill's config; nobody typed a password by hand.

NOT done: the signed-in screens (`/account/*`, `/admin/security`, onboarding, lock screens) against WaDesk. Stamp: `blocked-env`. Tracker rows stay `frontend-done`/`backend-done` until someone signs in to WaDesk and the signed-in twin specs run.
