# Wiring map: flow-builder-editor (FLB)

Read with [the inventory entry](../inventory/flow-builder-editor.md) and [the API doc](../../api/flow-builder-editor.md). `built` = in this repo and
tested; `intended` = deliberately different (reason in [parity/flow-builder-editor.md](../parity/flow-builder-editor.md) and
[flow-builder-editor-list.md](../parity/flow-builder-editor-list.md)); `owned:FLR` = built by the flow-runtime-engine domain;
`blocked:<domain>` = waits on a domain that does not exist yet; `wontfix` = dead code or dev fixture in WaDesk.

## How a flow gets from the editor to a run

| Step            | WaDesk                                                                             | Ours                                                                                                                                                                                               |
| --------------- | ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Design          | React canvas (htm) served from a Blade shell, state in the browser                 | Next.js client canvas (`features/flow-builder-editor/builder`), same palette, inspector and shortcuts                                                                                              |
| Save            | `POST flows/api/save`, encrypted JSON blob + plain trigger columns + a file mirror | `POST /v2/flows`, `PUT /v2/flows/:id`: jsonb graph, plain name, trigger columns re-derived in the same transaction, `rowVersion` lock                                                              |
| Keyword trigger | a hidden "managed" `keyword_replies` row mirrors every keyword flow                | none: FLR matches `flows.trigger_keywords` directly (WD-FLR-004, `intended`)                                                                                                                       |
| Sender          | `trigger_device_id`, polymorphic by `provider`                                     | `flows.trigger_channel_id` (FK to `channels`) resolved from the Trigger's `<engine>:<uuid>` key; `provider` stamp kept                                                                             |
| Publish / pause | `is_published`, `published_at`, `is_active`                                        | same columns; `automation` plan feature is the soft paywall                                                                                                                                        |
| Runtime fetch   | Node bridge calls `GET api/flows/{id}` and FlowNormalizer rewrites the graph       | FLR reads `flows` directly and compiles with its own `compileGraph`; `compileGraph` applies `flbToRuntimeData` (the editor-side FlowNormalizer mapping) to every node, so a saved graph runs as is |
| Delete          | `forceDelete`, children orphaned                                                   | hard delete, `flow_subscribers`, `flow_runs`, `flow_retry_logs`, `flow_connected_devices` cascade by FK                                                                                            |

## Consumers of the editor's data

| Reader                                  | Reads                                                                                                                        | Notes                                                                                                                                                        |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| FLR trigger service                     | `trigger_kind`, `trigger_value`, `trigger_keywords`, `trigger_channel_id`, `provider`, `is_published`, `is_active`           | written by the save, covered by e2e against FLR's real `FlowTriggerService`                                                                                  |
| FLR run start                           | `flow_data`                                                                                                                  | compiled by `compileGraph`                                                                                                                                   |
| FLR screens and public API              | `flows` (names, counts)                                                                                                      | names are plain text now (WaDesk encrypted them)                                                                                                             |
| FLR `AskFile` / `AskLocation` executors | `ask_file`, `ask_location` node data through `flbToRuntimeData` (`question`, `variable`, `extensions`, wait settings)        | park a `Custom` wait; the inbound hook (`InboundStoredEvent.message.media`) and `decodeInbound` carry the file's kind, mime, name and the location's numbers |
| Contacts (CRM)                          | `ContactsService.setPropertyFromFlow` writes one active contact property (the file link) for "Save the response as property" | no `contact.updated` event, so a flow cannot start flows of its own                                                                                          |
| Campaigns (flow as a send step)         | `flows` by uuid                                                                                                              | unchanged                                                                                                                                                    |
| Mobile app (`getflows`)                 | n/a                                                                                                                          | MOB domain                                                                                                                                                   |
