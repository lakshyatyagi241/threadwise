# Shopify and WooCommerce API

Base path `/v2`. Inventory: [inventory/shopify-woocommerce.md](../threadwise-port/inventory/shopify-woocommerce.md). The first two tables need a user
session and the permission shown; the platform routes need an operator; the callback is public and proves itself (a signature, a sealed state).

## Shopify (TW-ECOM-004 to 007, 013)

| Method and path                 | Permission     | What                                                                                                                                                                                                                                                                                                                       |
| ------------------------------- | -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /shopify`                  | `ecom.read`    | `{appEnabled, scopes, eventTopics, store}`: whether the platform app is on, what it asks for, the 12 webhook topics and the workspace's store (or null). Never a token.                                                                                                                                                    |
| `POST /shopify/connect/start`   | `ecom.connect` | Body `{shop}` (a handle, a `*.myshopify.com` name or a pasted address). 200 `{url}`: the store's approval page. 422 `ECOM_SHOP_INVALID`, 422 `ECOM_NOT_CONFIGURED`.                                                                                                                                                        |
| `POST /shopify/stores/:id/sync` | `ecom.connect` | Sync now: 200 `{ok, counts: {products, orders, customers}, importQueued}`. A store that does not answer is flagged `error` and answers 200 `{ok: false, message}`; a store whose app was removed asks to be connected again. 404 for another workspace's store. The import (every page, up to ten) runs in the background. |
| `DELETE /shopify/stores/:id`    | `ecom.connect` | 204. Removes the store's webhooks (errors ignored) and the row with its mapping and logs. 404 for another workspace's store.                                                                                                                                                                                               |

`ShopifyStore`: `id` (uuid), `storeUrl`, `storeName`, `status`, `connected` (credentials held), `connectedAt`, `lastVerifiedAt`, `productsSyncedAt`,
`ordersSyncedAt`, `customersSyncedAt`, `syncStats`, `webhookUrl`, `webhookIds` (topic to the store's id), `createdAt`, `rowVersion`, `shopId`, `shopEmail`,
`shopOwner`, `shopPlan`, `shopCurrency`, `shopCountry`, `scopes`.

## Shopify public route

| Method and path               | Proof                                         | What                                                                                                                                                                                                            |
| ----------------------------- | --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /shopify/oauth/callback` | the `hmac` over the query, the sealed `state` | Where Shopify sends the browser back. 303 to `{WEB_APP_URL}/shopify?shopify=connected\|error&message=...`. Refused with a message: a bad signature, an expired or unknown state, another store, a refused code. |

| `POST /shopify/webhook/:secret` | `X-Shopify-Hmac-SHA256` (base64 HMAC of the raw body, platform client secret) | 200 `ok`; 401 `bad hmac`; 404 `not found`; 503 `try again` (not queued, retry). Topic in `X-Shopify-Topic`, delivery in `X-Shopify-Webhook-Id`. |
| `POST /woocommerce/webhook/:secret` | `X-WC-Webhook-Signature` (the store's webhook secret) | As Shopify's with `bad signature`. Topic `X-WC-Webhook-Topic`, delivery `X-WC-Webhook-Delivery-ID`. A non-JSON ping is acknowledged and not logged. |

| `POST /shopify/compliance` | `X-Shopify-Hmac-SHA256` (platform client secret) | The three mandatory privacy webhooks by `X-Shopify-Topic`: `customers/data_request` (acknowledged), `customers/redact` (erases that customer's logs, all of the shop's when no phone), `shop/redact` (erases the store). 401 `bad hmac` before anything is read; 200 `ok` otherwise, whatever fails. |

## Shopify embedded app (TW-ECOM-038)

Public, read-only: nothing is signed in and no user session is minted. The proof is Shopify's App Bridge session token (a JWT, HS256, signed with the platform's client secret). Not yet exercised against a real Shopify: tested with generated, signed fixtures.

| Method and path                  | Proof             | What                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| -------------------------------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /shopify/embedded/config`   | none (public)     | `{appEnabled, clientId}`: the app's public client id so the page can load App Bridge; `clientId` is null while the app is off.                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `POST /shopify/embedded/session` | the session token | Body `{sessionToken, shop?}`. 200 `{shop, connected, store, message}`; `store` is `{id, storeName, status, shopPlan, connectedAt, lastVerifiedAt}` or null. A shop nobody connected answers `connected = false`, `store = null` and "open the app to connect". 401 `ECOM_SESSION_TOKEN_INVALID`: bad signature, algorithm other than HS256, expired or not yet valid (10 s skew), `aud` not the client id, `dest` not `https://<handle>.myshopify.com`, `iss` not that shop's `/admin`, or `shop` not the token's shop. 422 `ECOM_NOT_CONFIGURED` while the app is off. Rate limited per address. |

The answer never carries a token, the webhook address or the workspace. The web app serves `/shopify?host=...&shop=...` as `/shopify/embedded` (no menu, no sign-in) and sets `frame-ancestors https://admin.shopify.com https://*.myshopify.com` for it; every other route keeps `frame-ancestors 'self'`.

Give Shopify `{APP_URL}/v2/shopify/oauth/callback` as the app's redirect address (the platform setting defaults to it).

## Marketing consent of store customers (BL-167)

Customers are mirrored into contacts through `ContactsService.resolveOrCreateByIdentity` (audit, plan contact cap, default stage; quiet: no
`contact.created`). A customer's own marketing choice in the store is recorded in the consent ledger only when the merchant switched on the
store's consent line (`PUT /v2/contact-consent/notices/commerce/shopify:<id>` or `woocommerce:<id>`, the Settings tab). Shopify:
`email_marketing_consent` / `sms_marketing_consent` with state `subscribed`, or the older `accepts_marketing`. WooCommerce has no such flag; only
a checkout plugin's customer `meta_data` entry `accepts_marketing` or `marketing_consent` is read. Source `commerce`; the notice's `channels:
["whatsapp"]` also counts it for WhatsApp. Once per customer and wording version; never over a withdrawal.

## Automations (TW-ECOM-009, 033)

| Method and path                                      | Permission                | What                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ---------------------------------------------------- | ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /{shopify\|woocommerce}/stores/:id/automations` | `ecom.read`               | `{automations: [{eventType, isActive, templateUuid, templateName, varMap, sendTo, adminNumber, delaySeconds, fired}], senderKey}`: one row per event the store supports (18 Shopify, 21 WooCommerce), off when never set up. `fired` counts logged deliveries. `senderKey` is WooCommerce's "send from" or null.                                                                                                                                                                  |
| `PUT /{shopify\|woocommerce}/stores/:id/automations` | `ecom.automations.manage` | Body `{automations: [{eventType, isActive, templateUuid, varMap?, sendTo?, adminNumber?, delaySeconds?}], senderKey?}`. Saves all in one transaction (audited, outbox `*.automations.saved`) and answers the new list. Unsupported event types are ignored. 422: unknown or other-tenant template, an automation on without a template, a `senderKey` that is not a connected number. `senderKey` (`engine:uuid`) is WooCommerce only; `null` clears it, leaving it out keeps it. |

`varMap` is an ordered list of order field names (the variables in the event's context) filling `{{1}}`, `{{2}}`, ...; empty means the default `[name, order name, total]`. Only the cart steps (`cart/step2`, `cart/step3`) wait their `delaySeconds`; every other automation sends at once, as in Reference.

## Invoices (TW-ECOM-035)

| Method and path                                                | Permission             | What                                                                                                                                                                                                           |
| -------------------------------------------------------------- | ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /{shopify\|woocommerce}/stores/:id/invoice-policy`        | `ecom.read`            | `{autoInvoice, trigger}` of the workspace for this store type (`trigger`: `on_placed`, `on_paid` (default), `on_fulfilled`). The values are the invoice settings' `auto_send_<source>` and `trigger_<source>`. |
| `PUT /{shopify\|woocommerce}/stores/:id/invoice-policy`        | `ecom.connect`         | Body `{autoInvoice?, trigger?}` (at least one); audited and raised as `invoice_settings.updated`. 404 for another workspace's store.                                                                           |
| `GET /v2/invoices?source=shopify\|woocommerce` (invoicing API) | `record.invoices.read` | The Invoices tab's list. `source` is a new comma separated filter of the invoice list and counts.                                                                                                              |

No route for the hand-off. After the pipeline's mirror step, its own guarded `invoice` step calls the `PaidOrderHook` (`_shims/tokens.ts`, bound to `InvoicingPaidOrderHook`) with the delivery id (`X-Shopify-Webhook-Id`, `X-WC-Webhook-Delivery-ID`, else a hash of the body). One transaction: the switch is on (off by default), the trigger is met (`on_paid`: Shopify `orders/paid` or `financial_status = paid`; WooCommerce `processing`, `completed` or a `date_paid`; a cancelled, refunded, voided or failed order never), the plan has `invoicing`, the delivery is claimed (`ecom_invoice_handoffs`, unique per workspace, source and delivery id: a replay stops), then `ExternalOrderBillingService` makes the confirmed sales order, the invoice (`source` = `shopify` or `woocommerce`; a tax invoice when tax was charged, else a receipt), the ledger payment of a paid order and the `invoice.sent` event (WhatsApp, else email). An order with an invoice (even voided) is never invoiced again. A hand-off that throws is logged and never fails the delivery. A plan at its `invoices_monthly` limit leaves the order without an invoice (claim outcome `skipped`).

## Flow shop node: checkout links and purchase resume (TW-ECOM-036, 037)

No HTTP route. The flow runtime's Commerce shop node (Shopify, WooCommerce) calls `EcomFlowShop`, bound to its `FlowShopGate` at start.

| Call           | What                                                                                                                                                                                                                               |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `inStock`      | The retailer ids sellable now, from the mirrored products; unknown ids are kept; `null` for `whatsapp_shop`.                                                                                                                       |
| `sendNative`   | Always false here (the node sends its card stack).                                                                                                                                                                                 |
| `checkoutLink` | Shopify: Storefront cart (store with `metadata.storefrontAccessToken`) else draft order, note `threadwise-flow:<run>`. WooCommerce: pending order with meta `_wa_flow_session` = run. `null` when the store, product or API fails. |

`orders/create`, `orders/paid` (Shopify) and `order.created`, `order.updated` (WooCommerce) carrying the run reference advance the waiting run through `purchased`; the reference is a run uuid only, in the same workspace.
