Verdict: Partly met. Liveness, readiness, healthchecks and tests are in place for the API, web, worker, Postgres and Redis. Four things have no alert or probe, so "100%" with alert ownership is not met.

What this is

Liveness asks "is the process alive" and must never look at dependencies. Readiness asks "can it serve traffic now" and checks the database and Redis. A restart fixes a dead process, not a dead database, so mixing them turns a database blip into a full outage.

  • Only the API's own tsc/build was run; the full unit suite was not.
