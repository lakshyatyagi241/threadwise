# Runbook: manual test of a personal WhatsApp number on a real phone

Nothing in the engine has ever run against a real WhatsApp session: the automated tests use a fake socket. Run this checklist on **one real phone and a
spare number you can afford to lose** before any pilot workspace is allowed (spec decision D1 gates the pilot on counsel's review of the notice text as well).
Record the result in [parity/whatsapp-devices-baileys.md](../wadesk-port/parity/whatsapp-devices-baileys.md) (date, who, build, what passed, what did not).

Using it is against WhatsApp's terms and the number can be restricted or banned. Use a number that has no business value, link it from a phone that is not
your main one, keep volumes tiny, and never test with a number whose chats you cannot share with the workspace (every private chat on a linked number lands in
the shared inbox).

## Setup

1. A staging stack: API, **worker** (it holds the sockets; without it a pairing start answers 503 `WA_WORKER_UNAVAILABLE`), Postgres, Redis. Two workers for items 11 and 15.
2. Platform switch on, and the test workspace on the allow-list ([whatsapp-unofficial-switch.md](whatsapp-unofficial-switch.md)). Log in as an Owner or Admin
   of that workspace (they hold `wa.devices.*`). Use the `/devices` screen, or the API ([api/whatsapp-devices-baileys.md](../api/whatsapp-devices-baileys.md)) with a bearer token.
3. A phone with WhatsApp and the spare number, internet on, **fewer than 4 linked devices** (item 13 fills the limit on purpose).
4. Tail the worker log while you test: it must never print a QR string or a pairing code (any line that does is a defect).

## Checklist

Tick each, with the time and what you saw.

| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Add the number (name, country code, number, "use for sending after linking"), accepting the risk notice. Start a QR link, scan it with the same number's phone (Linked devices).     | The QR shows within about 35 s and refreshes about every 20 s; after the scan the state goes `awaiting_qr` to `connecting` (a "Syncing data" step is normal) to `connected`; the device is `active`; the QR is gone. |

| 7   | Type a message on the phone to a contact.                                                                                                                                            | It appears in the inbox once (an echo, not a duplicate).                                                                                                                                                             |
| 8   | Send a message in a WhatsApp group the number belongs to.                                                                                                                            | It is ignored (group messages are not threads).                                                                                                                                                                      |
| 9   | Restart the worker.                                                                                                                                                                  | The device reconnects without a scan within about a minute (state `connecting` then `connected`); no QR is requested. | 11  | With two workers running, kill the one that holds the device (`wa:device:<org>:<id>` lease).                                                                                         | The other adopts it after the lease expires (up to about 2.5 minutes); never two sockets for one number; messages keep flowing.                                                                                      |
| 12  | On the phone: WhatsApp > Linked devices > remove this device.                                                                                                                        | State `logged_out`, reason `unlinked_on_phone`; the session is wiped; the copy says WhatsApp ended the link (never "banned"); Link again works.                                                                      |
| 13  | Fill the phone's linked-device slots (4), then link this number.                                                                                                                     | State `error`, reason `device_limit_reached` with the "remove one in Linked devices" text.                                                                                                                           |
| 14  | Send a broadcast and a scheduled message on the number with the platform pacing set (`node.pacing`).                                                                                 | They are paced as configured; failures (if any) are visible; nothing is sent while the device is not connected.                                                                                                      |
| 15  | Remove the workspace from the allow-list, wait 30 s, then add it back.                                                                                                               | Every device call is 422 `WA_UNOFFICIAL_DISABLED`; the worker closes the socket within about 20 s (the phone shows the device offline, not removed); after adding the workspace back it reconnects without a scan.   |
| 16  | Delete the device (confirm), with it connected.                                                                                                                                      | The phone shows the linked device **removed**; the row is gone; its open conversations are closed but readable; the plan slot is free.                                                                               |

| 18  | In the web screens: right-to-left (Arabic), dark mode and a 390 px wide window.                                                                                                      | Every step of the wizard and the list are usable and readable. (Web part of the phase.)                                                                                                                              |
| 19  | Check the logs, the `event_outbox` and `audit_log` for the whole session.                                                                                                            | No QR string and no pairing code anywhere; events and audit rows exist for create, pairing start, connect, disconnect, delete and the acknowledgement.                                                               |
| 20  | Start pairings quickly: 6 in an hour on one device.                                                                                                                                  | The 6th is 429 `DEVICE_PAIRING_RATE_LIMITED` with `retryAfterS`; a second admin's start during an attempt is 409 `DEVICE_PAIRING_IN_PROGRESS`.                                                                       |

## After the run

- Delete the test device (item 16) and confirm on the phone that no linked device remains.
- Note anything WhatsApp-side that surprised you (a challenge, a temporary restriction, a message from WhatsApp): the pilot's own `logged_out` rate is the only
  evidence there will ever be about bans.
- A failure of any of items 1 to 5, 9, 12, 16 or 19 blocks the pilot.
