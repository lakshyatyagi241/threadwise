# Runbook: manual test of a personal WhatsApp number on a real phone

Nothing in the engine has ever run against a real WhatsApp session: the automated tests use a fake socket. Run this checklist on **one real phone and a
spare number you can afford to lose** before any pilot workspace is allowed (spec decision D1 gates the pilot on counsel's review of the notice text as well).
Record the result in [parity/whatsapp-devices-baileys.md](../threadwise-port/parity/whatsapp-devices-baileys.md) (date, who, build, what passed, what did not).

Using it is against WhatsApp's terms and the number can be restricted or banned. Use a number that has no business value, link it from a phone that is not
your main one, keep volumes tiny, and never test with a number whose chats you cannot share with the workspace (every private chat on a linked number lands in
the shared inbox).

## Setup

1. A staging stack: API, **worker** (it holds the sockets; without it a pairing start answers 503 `WA_WORKER_UNAVAILABLE`), Postgres, Redis. Two workers for items 11 and 15.
2. Platform switch on, and the test workspace on the allow-list ([whatsapp-unofficial-switch.md](whatsapp-unofficial-switch.md)). Log in as an Owner or Admin
   of that workspace (they hold `wa.devices.*`). Use the `/devices` screen, or the API ([api/whatsapp-devices-baileys.md](../api/whatsapp-devices-baileys.md)) with a bearer token.
3. A phone with WhatsApp and the spare number, internet on, **fewer than 4 linked devices** (item 13 fills the limit on purpose).
4. Tail the worker log while you test: it must never print a QR string or a pairing code (any line that does is a defect).

## Checklist

Tick each, with the time and what you saw.

## Groups of the number (API and Groups tab)

Same rules as above: a spare number, a second phone you control to play "the other person", the platform switch on and the workspace allowed. Needs the worker
running. Keep the platform's group limits at their defaults for the run (20 operations a minute, 5 creates a day), except where a row says otherwise. Write the time and
what you saw for each. Routes: [api/whatsapp-devices-baileys.md](../api/whatsapp-devices-baileys.md#groups-of-a-personal-number-v2devicesidgroups).

| #   | Do                                                                                                                                                            | Expect                                                                                                                                                                                                                                                                              |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| G1  | On the phone, make sure the number is in 2 groups (one where it is admin, one where it is a plain member). Connect it and open the Groups tab.                | Within about 10 seconds both groups are listed with the right names, member counts and admin flags; `GET .../state` says `ready`; no member number is on a list row.                                                                                                                |
| G2  | On the phone, rename the admin group and change who can send.                                                                                                 | The tab shows the new name and the "only admins send" flag within seconds, without a reload (a realtime hint), and no duplicate event rows appear in `event_outbox`.                                                                                                                |
| G3  | On the phone, add and then remove a member of the admin group.                                                                                                | After about 5 seconds the member count and the roster follow; one `participants_changed` event per change.                                                                                                                                                                          |
| G4  | In the tab, create a group with two numbers: your second phone, and a number whose privacy blocks adds from non-contacts (or a number not on WhatsApp).       | The group exists on the phone; the answer lists each number (`ok`, and `privacy_blocked` or `not_on_whatsapp`); the creator is you; an audit row `wa.group.create` exists.                                                                                                          |
| G5  | Create 6 groups in a day (or set `WA_GROUPS_CREATES_PER_DAY=2` first).                                                                                        | The call after the cap is refused with 429 `WA_GROUP_RATE_LIMITED`, scope `creates_day`, with `retryAfterS`; nothing reaches WhatsApp; the state shows 0 left.                                                                                                                      |
| G6  | Add the second phone to the group again, then promote it, then demote it, then remove it.                                                                     | Each is done on the phone; the answer for each is `ok`; adding someone already in says `already_member`; removing someone not in says `not_member`.                                                                                                                                 |
| G7  | In the plain-member group, try to add a person, to rename it and to change settings from the tab.                                                             | 403 `WA_GROUP_NOT_ADMIN` for settings and promote/demote (no WhatsApp call: the phone shows nothing); rename and add work only when the group allows members to.                                                                                                                    |
| G8  | On the second phone, join the admin group by its invite link while join approval is ON.                                                                       | A join request appears in the tab within seconds (a bell row "Someone wants to join ..." for people who manage groups, one row that counts up for several); approving it from the tab lets the person in; rejecting another keeps them out; the row closes when the queue is empty. |
| G9  | Show the invite link in the tab, then reset it; try the old link on the second phone.                                                                         | The new link works, the old one does not; the code appears in neither `audit_log`, `event_outbox` nor the API log.                                                                                                                                                                  |
| G10 | Set a PNG as the group picture; then try a GIF and an image over 5 MB.                                                                                        | The PNG shows on the phone; the GIF and the big file are 422 (no WhatsApp call).                                                                                                                                                                                                    |
| G11 | From the second phone (as admin) remove the number from the group.                                                                                            | Within seconds the group is marked left and read-only (still listed under "left"), and managers get a bell row "Removed from ...". Leaving a group yourself from the tab (or the phone) raises no such row.                                                                         |
| G12 | Leave the plain-member group from the tab.                                                                                                                    | It leaves on the phone; the row stays as left; a second leave is 409 `WA_GROUP_LEFT`; the inbox thread of the group is read-only.                                                                                                                                                   |
| G13 | Force a refusal: set `WA_GROUPS_OPS_PER_MINUTE=3`, then refresh 4 groups quickly.                                                                             | The 4th is 429 with scope `ops_minute` and `retryAfterS`; after a minute it works again.                                                                                                                                                                                            |
| G14 | Join a group by link with `WA_GROUPS_JOIN_BY_LINK_ENABLED` unset, then set to `true` and restart.                                                             | 422 `WA_GROUP_JOIN_BY_LINK_DISABLED` first; after the switch the preview names the group, the join works (or becomes a request when approval is on); the 6th of the day is 429.                                                                                                     |
| G15 | Stop the worker, change something on the phone, start the worker; wait for the sweep (set `WA_GROUPS_SWEEP_HOURS=1` for the run) or press Refresh in the tab. | The directory catches up (the change is shown, a group you left on the phone is marked left); no tight loop of reads in the logs (at most one list read per window).                                                                                                                |
| G16 | Open `/store/groups` (Store) before and after G4 and G11.                                                                                                     | The new group is listed with its member count and can be given an ordering code; a group the number left keeps its row and code.                                                                                                                                                    |
| G17 | A workspace off the allow-list: open the tab and call the routes.                                                                                             | 422 `WA_UNOFFICIAL_DISABLED` everywhere; nothing is written to `wa_device_groups` even when the phone changes a group.                                                                                                                                                              |
| G18 | A member without `wa.groups.manage` opens the tab.                                                                                                            | They see the list and counts (read key) but no member numbers, no join requests and no invite link (403).                                                                                                                                                                           |
| G19 | Check the logs, `event_outbox` and `audit_log` for the whole group session.                                                                                   | No invite code, member number or subject in any log line, event payload or audit delta.                                                                                                                                                                                             |

## After the run

- Delete the test device (item 16) and confirm on the phone that no linked device remains.
- Note anything WhatsApp-side that surprised you (a challenge, a temporary restriction, a message from WhatsApp): the pilot's own `logged_out` rate is the only
  evidence there will ever be about bans.
- A failure of any of items 1 to 5, 9, 12, 16 or 19 blocks the pilot.
