3. What is this, in plain words

An upload is a file a stranger hands the app. The app must check what the file really is, how big it is, and what it is called, and must never let the browser run it. Analogy: a post room that opens every parcel, ignores the label the sender wrote, and files it under a number it picks itself.

Glossary
Magic bytes: the first bytes of a file that say what it really is (a PNG starts with the same 8 bytes).
Extension spoofing: naming an HTML file photo.png.
Polyglot: one file that is valid as two formats at once.
Path traversal: a file name such as ../../x that tries to escape the upload folder.
Zip bomb: a tiny zip that expands to gigabytes.
Ratchet: a test that only lets things get stricter; a new upload route fails it until someone reviews the route.

4. How we tested

  1. Inventory: grep for FileInterceptor and friends (25 files).
  2. Hostile payloads: double and trailing extensions, .html, .svg, .php, HTML bytes under a PNG name, a PDF named PNG, empty and oversized files, names with ../, absolute paths, NUL, right-to-left override, markup padded past 1 KB, nine active SVGs, a zip that inflates to 80 MB under a header that declares 100 bytes.
  3. Ratchet: every interceptor needs limits.fileSize; every file must be in the reviewed list; stale entries fail too.
  4. Live: run.sh --quick posts a hostile multipart body without credentials to every multipart or upload-named write operation in the OpenAPI document.

8. What this does NOT prove

  • No authenticated live upload per route; the guards are tested in process, and the ratchet checks only that a size cap exists and the route was reviewed, not that each controller really calls the guard (the manifest note records what was read).
  • No cross-tenant download or delete (IDOR) test, no real S3 or object store, no storage-quota test.
  • No CSV formula injection test on import (export side is covered by the VAPT suite); no import-size timing.
  • No WhatsApp media, email attachment or flow-builder asset live test.
  • No rate limit test on upload routes.
  • Per-route Content-Disposition was read in a few controllers, not asserted for all.
  • The runner uses a throwaway database only to boot the API; it does not run in CI yet.
