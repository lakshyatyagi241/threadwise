1. What was tested and how

  1. Inventory. Every file under apps/api/src that makes an outbound HTTP call was read and classified: fixed vendor host, guarded, operator-set, or reachable by a tenant.
  2. Address matrix (address-matrix.spec.ts). One list of 35 must-block and 5 must-allow addresses run against the address rule of all 7 guards: loopback, RFC1918, CGNAT, link-local and cloud metadata, documentation and benchmark ranges, IPv6 loopback, IPv4-mapped (dotted and hex), NAT64, 6to4, Teredo, ::127.0.0.1, and text that is not an address.
  3. URL matrix (url-matrix.spec.ts). 41 hostile URL spellings run against 5 entry points (flow-builder guard, webhook guard, SafeFetch, guardedRequest, WABA provider guard): decimal, hex and octal IPs, 127.1, trailing dot, localhost variants, userinfo tricks (good@127.0.0.1, 127.0.0.1#@good), unicode digits, IPv6 forms, and the schemes file, gopher, ftp, dict, javascript. Names resolve through a fake resolver; no real internal address or production host is contacted.
  4. Redirects. A local server answers 302 to a second local listener standing in for an internal service. SafeFetch and guardedRequest must return the 3xx and the internal listener must receive 0 hits.
  5. Ratchet (outbound-ratchet.spec.ts). Scans every source file; a bare fetch() (which follows redirects) fails unless the file is on a reviewed list with a stated reason. This stops the problem from coming back and forces review of new outbound code.

4. Automation

Workflow .github/workflows/ssrf-audit.yml runs the suite on pull requests that touch guards or outbound callers, nightly, on release, and manually, and keeps the JUnit report for 90 days. Any failing case fails the job.

5. Not fixed, and why (needs a decision)

  • LibreTranslate endpoint (localization-translation): operator-set; private ranges are allowed on purpose and the guard is a string check. Moving it to guardedRequest with an allow-private flag would be correct but could break self-hosted set-ups. Medium, operator only
  • Payment gateway drivers (payment-driver.ts): bare fetch; not yet confirmed whether any driver takes a tenant base URL. Listed in the ratchet with that note. Low, unconfirmed
  • Fixed-host vendor calls (Google, Meta, Telegram, Twilio, AI vendors, FX rates): hosts are constants; env overrides are deploy-time only. They still follow redirects; left as they are and recorded in the ratchet list.
  • Not reviewed in depth: node-bridge-runtime/proxy.ts (operator proxy test), SMTP host, setup-wizard database host.

6. Limits of this test

  • Unit-level with fake resolvers and local listeners. It does not prove how NAT64/6to4 routes behave on a particular host network.
  • No live DNS-rebinding server was used; rebinding is closed by design (check inside the socket lookup), not shown by a timing test.
  • In the checkout used for this run, 18 other unit test files cannot load because @nestjs/swagger cannot resolve @nestjs/common/interfaces with the locked versions. The lockfile is untouched by this change, but those suites were not exercised here and should be checked in CI.
  • The code survey was a read, not an exploit attempt. Operator-only findings assume the operator is trusted.
