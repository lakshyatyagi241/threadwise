# Text and translations in the mobile app

The rule is the web app's: **every user-visible string comes from the message files, in all 21 locales, in the same change.** English-only is never done.
The files are `apps/mobile/src/messages/<locale>.json` (one per locale, `en` is the source): the same 21 locales as `apps/web/messages`, plus Marathi (`mr`), which the app has had from the start. That makes 22 files.

## Adding or changing text

1. Add the key to `src/messages/en.json` under a group that matches the feature (`auth`, `home`, `inbox`, …). Use plain keys (`signInTitle`), `{{name}}` for values. Text that depends on a count uses i18next plurals (`key_one`, `key_other`); other languages need other forms (Arabic six, Russian and Polish four, Japanese only `other`), and `i18n:check` requires exactly the forms `Intl.PluralRules` lists for that language.
2. Use it: `const { t } = useTranslation(); … {t('auth.signInTitle')}`. Keys are typed from `en.json`, so a typo is a compile error.
3. Translate it into the other 21 locales (the `mobile-i18n-sync` skill does this and checks it). Keep every `{{placeholder}}` exactly as in English.
4. `pnpm --filter @crm/mobile i18n:check` must pass: no missing key, no extra key, no empty value, no value still equal to the English text, placeholders identical.

A word that is genuinely the same in a language (a loanword such as "Password" in Italian) is listed in `scripts/i18n-same-as-english.json` (`{ "it": ["auth.password"] }`) with the locale and key; do not use it for text you did not translate.

## What is not allowed (lint errors)

- Text between JSX tags: `<Text>Hello</Text>`.
- A string literal in `label`, `placeholder`, `title`, `accessibilityLabel` or `accessibilityHint`.
- `Alert.alert(...)`: render the message in the screen so it can be translated and tested.

Server messages (`ApiError.message`, problem `title`/`detail`) are English and for logs. Show text chosen by the error **code** (`messageForError`, or a screen's own code→key map).

## Language and direction

The language is the first of the phone's preferred languages that the app supports (`detectLocale`; Chinese in any script maps to `zh-CN`), otherwise English. Latin and Cyrillic languages are drawn in Inter like English; the others (Devanagari, Bengali, Arabic, Hebrew, Urdu, Thai, Chinese, Japanese, Korean) in the phone's own font (`usesShapedScript`). Right-to-left (Arabic, Hebrew, Urdu) follows the phone's layout direction; use
`marginStart`/`paddingEnd`/`start`/`end` rather than left/right, and check a screen in an RTL language before calling it done. A language picker inside the app arrives with the settings screen.

## Dates, numbers and money

Format with `Intl` (`toLocaleString`, `Intl.DateTimeFormat`, `Intl.NumberFormat`) using the active locale, never by hand. Money stays a string from the API until a decimal library (`@crm/tax`) touches it (CONTRIBUTING rule 5).
