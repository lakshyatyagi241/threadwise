# Quality: how to run what is here

Everything the QA plan added lives under `docs/quality/` (documents and generated reports), `tools/quality/` (small Node tools with
their own tests) and `apps/api/test/` (the suites). Nothing runs automatically on GitHub today: the check workflows were removed in
#328 and jobs do not start on this account. The `Security` and `Quality` workflows are manual (`workflow_dispatch`), and every
command below runs on a laptop.

## One command per question

| Question                                                                                                                                                                                                                   | Command                                                                             | Details                                                                                      |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| Do the quality tools work?                                                                                                                                                                                                 | `node --test tools/quality/*.test.mjs`                                              |                                                                                              |
| Does every module have an edge-case file, and is each case traced to a test?                                                                                                                                               | `node tools/quality/check-edge-cases.mjs` (`--strict` fails on an untested P0 case) | [edge-cases/REPORT.md](edge-cases/REPORT.md)                                                 |
| How many acceptance criteria have a test that names them?                                                                                                                                                                  | `node tools/quality/check-acceptance-coverage.mjs`                                  | [functional-testing.md](functional-testing.md), [acceptance/REPORT.md](acceptance/REPORT.md) |
| Is `acceptance.json` stale?                                                                                                                                                                                                | `node tools/quality/extract-acceptance.mjs --check`                                 |                                                                                              |
| How many journeys run?                                                                                                                                                                                                     | `node tools/quality/journeys.mjs`                                                   | [journeys/journeys.json](journeys/journeys.json)                                             |
| Do unit tests pass, and how much business logic do they cover?                                                                                                                                                             | `pnpm --filter @crm/api test:coverage` and `pnpm --filter @crm/web test`            | [unit-testing.md](unit-testing.md)                                                           |
| Which database reads run once per item in a loop (N+1), and which are fixed?                                                                                                                                               | `pnpm qa 43`                                                                        | [n-plus-one-report.md](n-plus-one-report.md)                                                 |
| Do the queues and outbox subscribers line up?                                                                                                                                                                              | `pnpm --filter @crm/api exec vitest run test/unit/infra`                            | [integration-testing.md](integration-testing.md)                                             |
| Do the API's responses, errors and documents match their contracts?                                                                                                                                                        | `pnpm --filter @crm/api exec vitest run test/e2e/contract` (Docker)                 | [contract-testing.md](contract-testing.md)                                                   |
| Does a bad request get refused cleanly?                                                                                                                                                                                    | `pnpm --filter @crm/api exec vitest run test/e2e/negative` (Docker)                 | [negative-testing.md](negative-testing.md)                                                   |
| Does a repeated request do its work once?                                                                                                                                                                                  | `pnpm --filter @crm/api exec vitest run test/e2e/double-submit` (Docker)            | [idempotency-audit.md](idempotency-audit.md), [ADR 0029](../adr/0029-idempotency.md)         |
| Do the end-to-end journeys pass?                                                                                                                                                                                           | `pnpm --filter @crm/api exec vitest run test/e2e/journeys` (Docker)                 |                                                                                              |
| Is the repository free of secrets, vulnerable packages and image findings?                                                                                                                                                 | `bash tools/quality/security-scan.sh`                                               | [../runbooks/dependency-audit.md](../runbooks/dependency-audit.md)                           |
| Where does each QA-plan task stand (UI scenarios, regression, session expiry, SAST, injection, XSS, audit log, DB indexing, slow queries, plans, N+1, pool, transactions, constraints, integrity, retention, stress, CPU)? | `pnpm qa` (`pnpm qa 30 31`, `pnpm qa -- --fail`)                                    | [../../tools/qa-suite/README.md](../../tools/qa-suite/README.md)                             |

"Docker" means Testcontainers starts a Postgres and a Redis per test file.
