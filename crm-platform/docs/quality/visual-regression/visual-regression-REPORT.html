How it avoids flakiness

Everything that changes between two runs of the same page is removed, not tolerated: the browser clock is fixed (2026-01-15T09:30:00.000Z), language en-US, time zone UTC, reduced motion, animation and caret off, Math.random seeded, cookie consent pre-set, and text that is a date, a clock time or a relative time is rewritten to one fixed string. The page is measured until it stops changing (no data request in flight, every image decoded, no spinner, the same text and height on four polls in a row) instead of waiting a fixed time. The comparison allows 0.2% of pixels to differ, as a last resort. Every P0 scenario runs three times and any that does not give the same answer each time fails the run. A canary (a red band added to the login page) must fail the comparison, so the suite cannot go blind.

Limits

Chromium only (cross-browser is a separate suite); baselines belong to Linux Chromium and must be recorded there; the first paint of each page is compared, not interactions or open dialogs; the seeded workspace is mostly empty, so pages are compared in their empty and default states; GitHub Actions does not start on this account, so the workflow has not run in CI.
