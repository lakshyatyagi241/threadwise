# Idempotency audit: outbox subscribers and queue processors

Companion to [ADR 0029](../adr/0029-idempotency.md). Date: 2026-10-14. QA task 71.

**How it was done, and how far to trust it.** Every subscriber (files with `eventTypes`, 41 in `apps/api/src`) and every queue processor (31 files with `@Processor` or
`new Worker`) was scanned for the guard the class says it has. **Checked** = I read the line that does the work (cited). **Stated** = the class comment says it is
idempotent and names the mechanism, but I did not follow it into the service. Nothing here was run: this environment has no Docker, so the interceptor spec
(`apps/api/test/unit/common/idempotency.interceptor.spec.ts`) and the double-submit e2e changes are written but not executed.

Mechanisms: `dedupe-key` (insert `ON CONFLICT DO NOTHING` on a key built from the event id), `claim` (a status row moved before the external call),
`state-guard` (acts only while the row is in the expected state), `upsert` (set to a value), `jobId` (deterministic queue id), `port-dedupe` (an adapter dedupes on the key), `none`.
