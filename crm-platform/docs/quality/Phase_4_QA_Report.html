What was built

  • Firefox, WebKit and mobile-Safari projects in apps/web/playwright.config.ts (CROSS_BROWSER=1); E2E_PRIORITY=P0,P1 selects tests by priority.
  • e2e/priority.json maps each e2e folder to P0, P1 or P2; tools/quality/check-browser-priority.mjs fails on an unclassified or stale folder. Priorities are per folder, not per-test tags.
  • e2e/cross-browser/sign-in-and-locale.spec.ts: sign-in form, language menu, RTL (ar, he, ur), theme persistence, consent banner, keyboard.
  • e2e/_matrix/stub-api.mjs and QA_MATRIX_SCOPE=public: run the 19 public routes without the backend.
  • Manual workflow .github/workflows/browsers.yml and docs/quality/cross-browser-testing.md.

Findings and triage

  • Real defect, fixed: decorative mock-up <button>s on the home and features pages had no accessible name in every engine; now aria-hidden divs with the same classes (no visual change).
  • Environment: Firefox 500 /api/v2/i18n/languages came from a web proxy with no API behind it; stand-in API added.
  • Test assumptions corrected: the theme cookie is written after the colour flips (tests now wait for it); the site is light by default, not OS-driven.
  • Engine behaviour: Safari does not Tab to buttons by default; that one keyboard test is skipped on WebKit.

What is still open

  • Authenticated P0/P1 specs and the 189 authenticated routes were not run on Firefox or WebKit (need Docker stack).
  • The public matrix was not re-run after the accessible-name fix, so that the fix is confirmed on the three engines is still to do (one command, in the guide).
  • The repeat-run stability check (--repeat-each=3) result was not captured; the spec passed with 0 flaky on the single full run.
  • browsers.yml has not run on GitHub; type-check and lint of apps/web were not run (web dependencies not installed in the final session); Prettier and the Node tool tests were.
