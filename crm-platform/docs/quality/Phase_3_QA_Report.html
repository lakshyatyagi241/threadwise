Phase 3 QA Report

Reports for five tasks from the team sheet: API contract testing, integration tests, functional scenarios, unit tests with coverage, and end-to-end journeys. Each report says what kind of work it is, what it covers, the tools used, what was run, what was found, and where it falls short of the sheet's target. None of the five reaches its numeric target. The sheet's targets are volumes (30,000 unit tests, 10,000 scenarios, 4,500 integration tests, 5,000 contract assertions, 1,200 journeys); this phase built the machinery to measure each one, ran what could run, and produced the first honest numbers.

What changed in how this was run. Phase 2 could not run any vitest test because the dependencies would not install. This phase found the single blocked dependency (a GitHub-hosted libsignal fetch, HTTP 403), installed everything else in a scratch copy with that one package stubbed, and could then run the full API and web unit suites, measure coverage for the first time, and typecheck the API source and tests. That also ran last phase's idempotency.interceptor.spec and negative.spec (all pass) and the typecheck of every Phase 2 file (clean). Docker is still unavailable, so everything that starts Postgres and Redis (the e2e, integration, contract, negative and journey specs) is written but not run.

The most useful findings were about the tooling itself: coverage could not start at all (@vitest/coverage-v8 5.0.3 against vitest 2.1.9), vitest wrote no report when any test failed, two unit tests were failing on main, and only 5.1% of the acceptance criteria in the inventory are traceable to a test (3,554 have no test at all).

Nothing here runs on GitHub automatically: the check workflows were removed in #328 and jobs do not start on this account. The new Quality workflow is manual, like Security, and has never run.
