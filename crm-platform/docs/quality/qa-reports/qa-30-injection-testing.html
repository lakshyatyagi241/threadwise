Weak points

MediumSafety depends on every caller passing a literal

Helpers such as channelOwnerSql(alias) accept a string and put it in the SQL unescaped. Today the callers pass literals; a future caller passing request text would be injection. Fix: validate aliases against /^[a-z_][a-z0-9_]*$/i inside the helper, use sql.identifier() for names, and add a lint rule that flags sql.raw with a template interpolation.

MediumThe live attack suite has not run

About 30 SQLi/NoSQLi/command/header payloads against every parameterless GET route, login and headers are implemented but need a localhost API. Until it runs, the target is shown by code analysis only, not by an attack.

LowOne reviewed exception still needs a confirmation

The marketplace browse sort relies on a fixed map keyed by an enum; its baseline note says to confirm q.sort is validated by the zod enum. That confirmation is not recorded.

How to finish this task

  • Run the live attacks: API_URL=http://localhost:3000 QA_EMAIL=… QA_PASSWORD=… pnpm qa 30 (localhost only; other hosts are refused).
  • Read the 9 runtime template queries and baseline them with a reason, or fix them.
  • Add the lint rule and the alias validator above.
  • Run it on every PR and nightly, as the target states, and check that CI actually runs pnpm qa.
