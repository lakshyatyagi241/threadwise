Weak points

MediumUnused-index and plan checks need a live database

The check that lists indexes never used since stats reset (pg_stat_user_indexes) was skipped because DATABASE_URL was not set. Without it, "unjustified" indexes cannot be identified, only "redundant" ones.

LowStatic model of the schema

Indexes come from reading the SQL migrations (including drops and renames), not from a real database. A hand-made index in production would be invisible, and so would an index that exists in a migration but failed to build.
