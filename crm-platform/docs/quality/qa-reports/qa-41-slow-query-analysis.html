What was found

Passpg_stat_statements is preloaded in 3 of 3 Postgres definitions

deploy/hostinger/docker-compose.yml pass docker-compose.prod.yml pass docker-compose.yml pass. Each starts Postgres with shared_preload_libraries=pg_stat_statements and pg_stat_statements.track=all; migration 20261211100000 creates the extension (guarded, idempotent). apps/api/test/integration/db-guards.spec.ts proves the library is preloaded and queryable on a fresh database.

PassSlow statements are logged in 3 of 3

Threshold is 100 ms for this task, so queries between 100 and 500 ms are NOT captured in the log; pg_stat_statements covers them.

Reviewauto_explain is not enabled (optional)

deploy/hostinger/docker-compose.yml, docker-compose.prod.yml, docker-compose.yml: plans of slow statements are not captured automatically. Adding auto_explain with auto_explain.log_min_duration set to the threshold would record the plan of every slow query as it happens.

Not runRanking and p95 need a live database

Parsing the Postgres log (QA_PG_LOG) and ranking statements by total and mean time from pg_stat_statements (DATABASE_URL) were skipped, so 0 statements were ranked and the critical p95 target is not measured.

Weak points

MediumExisting databases keep the old settings until Postgres restarts

shared_preload_libraries is read at start. A running production database captures nothing until it is restarted with the new setting. Plan the restart in a maintenance window.

MediumThe log threshold is above the 100 ms target

Everything between the target and the logged threshold is visible only through pg_stat_statements, which stores totals and means, not a histogram. The p95 the check reports is an estimate (mean + 1.645 × standard deviation, assuming a normal shape) and will be wrong for skewed timings. Fix: lower the threshold for the measurement run, and take p95 from load-test traces (task 54) rather than from the estimate.

LowOverhead and reset

pg_stat_statements.track=all adds a small per-statement cost, and its counters reset on pg_stat_statements_reset() or a restart. Take a ranking after each load run before resetting.

How to finish this task

  • Run the load test first (task 54), then: DATABASE_URL=… QA_PG_LOG=/path/to/postgresql.log QA_SLOW_MS=100 pnpm qa 41 against a seeded database.
  • Restart the production Postgres to pick up the preload; verify with SHOW shared_preload_libraries.
  • Optionally enable auto_explain; record the top-10 statements and their before/after times in docs/quality.
