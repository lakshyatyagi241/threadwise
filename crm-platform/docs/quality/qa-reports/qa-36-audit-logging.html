Weak points

MediumApplication-role bypass remains possible

The append-only trigger allows DELETE when app.privileged is on. Anything that can already run arbitrary SQL as the app role can set it. The trigger closes bugs and ordinary sessions, not a full SQL-level compromise. The export plus the retention window are the second line.

LowThe coverage check counts audit calls per module, not per route

It reads each module's own files, so a controller that delegates to another module's service looks unaudited (handled through the baseline), and a module with one audited route and one unaudited route passes. Treat it as a floor, not proof every mutation is recorded.

LowBehavior tests need the Docker stack

The e2e suite (apps/api/test/e2e/audit-log) proves a row appears after a real mutation; it was not run by this report.

How to keep this task green

  • Run the guard spec any time: pnpm --filter @crm/api exec vitest run test/integration/db-guards.spec.ts --testTimeout=120000.
  • Run the audit-log e2e suite against the Docker stack and keep it in the nightly run.
  • Run pnpm qa 36 -- --fail in PR checks so a new module cannot ship without audit calls.
