Weak points

MediumPublic custom JavaScript and CSS are raw by design

site-head.tsx:37-38 writes super-admin custom JS and CSS straight into every public page. A compromised or phished super-admin account becomes site-wide script execution. Fix: require MFA and a re-auth for that setting, record every change in the audit log, and consider serving custom JS from a separate origin with a CSP.

MediumSeveral sinks rest on a server sanitiser staying in every write path

Blog, legal pages, CMS rich text, footers and email templates are safe because the server sanitises on write (and often on read). A new write path that skips HtmlSanitizerService would silently reopen all of them. Fix: sanitise on read as well wherever it is not already, and add a test that every route which stores HTML runs it.

Medium5 sinks were not traced and no review is recorded

Until each is traced and written to baseline.json with a reason, the task cannot turn green, and a later change to those values would not be noticed. Not traced: kit.tsx:661, site-head.tsx:14,21, hero.tsx:16, product-detail.tsx:386.

LowBrowser and live checks have not run

The Playwright spec (16 payloads on stored and reflected pages) exists but was not executed, and the live reflection/header check needs a localhost API and web app. CSP, nosniff and Referrer-Policy are configured, and CSP script-src does not allow 'unsafe-inline' in code.

What passes

  • No insertAdjacentHTML, document.write, javascript: URL literals or Function/eval strings in 3,204 scanned files.
  • A server-side HTML sanitiser exists and its tests contain 17 attack strings.
  • CSP, nosniff and Referrer-Policy are configured; CSP does not allow 'unsafe-inline' scripts in code.
  • A browser XSS spec exists: 16 payloads against stored and reflected pages.
