What is this, in plain words

A log line is a note the program writes about what it just did. Structured means each note is one line of JSON with the same named fields, so a person or tool can filter "everything request abc-123 did" or "everything workspace 7 did". Think of a ship's log where every entry has a date, a ship, a page number and a handwriting a machine can read. The danger is the other direction: a secret written into the log is readable by everyone who can read logs.

Glossary. Request id: a label given to one incoming call, repeated on every line it causes. Tenant / org id: the customer workspace. Redaction: removing secrets before writing. Ratchet test: a test that only lets a number get better (here: no new console.log). Outbox: the table where an event is saved so the worker can handle it later. pino: the JSON logger library.

How we tested

  1. Read the logger set-up, middleware, error filter, masking helper, outbox and worker; find the gaps.
  2. Boot the real API (node dist/src/main.js, port 3917, Redis db 14) and send 4 requests: health, a 404 with ?token=, an unauthenticated 401, a public tokenised URL. Analyse every line.
  3. Write the HTTP test first, watch it fail on real output (3 failures, then 1), fix the shared code, repeat.

What this does NOT prove

  • The tenant id test uses a simulated guard that sets the org on the context; a real JWT login, impersonation and a request that switches tenant were not run, so "never another tenant's id" is shown only for that path.
  • The worker process and the BullMQ processors were not booted; the worker's fields are checked by a unit test of the shared options and the outbox change only by a source assertion.
  • Scrubbing is pattern based. A secret in an unusual shape, or typed by a developer into a free-text message, is not caught (O4). Phone and card-like fields in free text were not tested.
  • Request bodies are not logged by pino-http at all; a 5 MB body test shows no line over 8 KB. Business code that logs a body itself was not searched.
  • Sentry scrubbing (separate code) was not re-tested here. Production shipping, retention and access to logs are out of scope.
  • Production mode with pino-pretty (NODE_ENV=development) prints human text, not JSON, by design.
  • The full API unit suite was not run (17 minutes); only the touched suites (293 tests in 15 files) plus tsc, ESLint and Prettier.
