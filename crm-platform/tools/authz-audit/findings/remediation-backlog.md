## Decisions needed (policy, not bugs)

- **Masked custom fields:** `isMasked` custom fields are returned in clear by `GET /v2/contacts/:id` to a reader without the properties permission. Intended?
- **`GET /v2/waba/webhook-config`** returns `verifyToken` in clear to the admin (allow-listed in the test). Keep?
- **`PATCH /v2/flows/:id/rename`** ignores `rowVersion` (no 409 on a stale write). Keep?

- **Billing visibility:** `GET /v2/billing/status|usage|entitlements` answer every signed-in member, any role (AUTHZ-062). Keep, or require `plan.subscription.read`?
- **Operator routes:** 270 operator/partner routes pass for any operator role (`OperatorGuard` only); 71 use `PlatformPermissionGuard`. Which need a platform permission key (AUTHZ-008/021/025)?
- **Role managers (lifecycle agent):** may strip grants from, or delete, a custom role holding keys they lack; may add `deny` grants for keys they do not hold; `admin.user.manage` alone can create a role-less user with an admin-set password. Intended?
- **Suspended/removed members** can still sign in (WD-AUTH-016) but receive no workspace data. Intended (WaDesk parity)?
- **API keys:** `scopes: []` means full access; removing the last scope of a key via a future edit endpoint would widen it silently; the console shows a key with only unknown scope names as `scopes: []`; any member with `api.keys.read` sees every key of the workspace; foreign ids in a broadcast `recipients` array are dropped, not rejected.
- **Deny by default:** `PermissionsGuard` lets undeclared routes through (106 authenticated-only routes today, all declared in `policy/self-service.json`). Add an explicit `@SelfService(reason)` decorator and fail closed?
