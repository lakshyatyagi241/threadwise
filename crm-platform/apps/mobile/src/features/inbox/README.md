# Inbox

The conversation list (`inbox-screen.tsx`) and one conversation (`thread-screen.tsx`, route `/conversation/[id]`), laid out like the
reference mobile app. Every control calls the real API; a control with nothing behind it is left out and recorded below.

## A conversation

| Part                   | What it is                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Header                 | back, avatar and name, the channel (its logo and the word for its kind), the reply-window timer, resolve or reopen, and the three dots                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Timer ring             | the 24-hour reply window (`detail.window.expiresAt`): hours and minutes left in the middle, a ring that empties (green, amber in the last hour, red when closed). Plain views, no drawing library                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Three dots             | the four lines the reference app has: **View details**, **Change status** (a sheet of the statuses the current one allows: pick, then Save; `POST .../status`, `inbox.conversation.resolve`), **Assign labels** and **Assign agent** (every active member with online/away/busy/offline and how many open conversations they have, and the teams; pick one in each, then Save: `GET /inbox/assignees`, `POST .../assign` with only what changed, `inbox.conversation.assign`). **Mark as spam** is last (`POST .../spam`, `inbox.conversation.resolve`, the web's "Mark as spam"); on a spam thread the line is not offered and the header button reads **Not spam**, which moves it back to open (the status route, spam to open). A line a person may not use is left out. Priority, snooze and waking a snoozed conversation are on Chat details; **Assign to me** is on the line above the box |
| Line above the box     | who has the conversation ("Assigned to Asha", "Assigned to you", the team, "Not assigned") and **Assign to me** when it is not yours and you may take it. The box stays usable: the web inbox lets anyone with the reply right answer, so this is information and a shortcut, not a lock (the reference mobile app locks the box to the assigned agent)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Chat details           | tap the name at the top, or the three dots (route `/conversation-details`): the contact (call, open the record, email, stage, owner, source, lead score), the **actions** (status, priority, snooze, labels, assigned agent and team: each opens its pick-then-Save sheet; **Wake up now** for a snoozed conversation), the channel and reply window, the team's **internal notes** (add with `inbox.conversation.note`; delete your own, or anyone's with `assign`), the activity **timeline** and the customer's **previous conversations** (tap to open). It is the web inbox's contact panel                                                                                                                                                                                                                                                                                                   |
| Assign labels          | the conversation's labels, as in the reference inbox (`GET /inbox/labels`, `POST` and `DELETE /inbox/conversations/:id/labels`): tick to put one on or take one off, type a name to make a new one (`inbox.tag.manage`). Needs `inbox.conversation.tag`. The names of the labels the thread has show beside the button. The library is shared with contact tags, but a label on a thread is not a tag on the contact                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Message bubbles        | words, the picture (loaded with the person's token), files as tiles (name and size), places, shared contacts, a template's header, footer and buttons, buttons an agent sent (web links open)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Bar under the messages | a message box while the 24-hour reply window is open. While an AI agent has the conversation and no person does: "This is a bot conversation." and **Assign to yourself** instead (the box returns once a person has it). When the window is closed WhatsApp allows only an approved template, so the box is replaced by that reason and **Send Template**: it opens the templates of the conversation's number (`GET /inbox/conversations/:id/templates`, searchable); one with no variables is sent when pressed, one with `{{n}}` slots asks for each value, then `POST .../messages` with `kind: template`. A template the app cannot fill in yet (media or variable in the header, a variable in a button link, named variables, paused, one-time-password) is listed greyed out with the reason                                                                                              |

Pictures: the API's link (`/api/v2/media/<token>`, made for the web app's proxy) is rewritten to the API and fetched with
`Authorization: Bearer`. React Native 0.86 on Android sends the headers of an image source only when the source is a **list**
(`source={[{ uri, headers }]}`); given one object it drops them silently and the picture is refused with 401. Do not "simplify" it.

## The list

The app keeps one live connection while a person is signed in (`src/lib/realtime`, the web's Socket.IO protocol with the one-time ticket from
`POST /v2/realtime/ticket`, ADR-0024; the provider is mounted in the signed-in layout). The server pushes hints, never data: the Inbox tab
reads the list (and that conversation) again when a conversation changes, its unread count moves or it is assigned
(`inbox.conversation.upsert`, `inbox.unread`, `inbox.assignment`, all on the person's own room), and an open thread joins its conversation room
and reads its messages again when one arrives or a tick changes (`inbox.message.new`, `inbox.message.status`). Everything is read again after
the connection comes up, after a skipped sequence number, when the server asks, and when the app returns from the background after 20 seconds
or more. **The 15-second timers (`INBOX_POLL_MS`, `THREAD_POLL_MS`) now run only while the live connection is not up** (the socket is down, or the
server would not let the person into that thread's room), so a dropped connection is covered by itself. The dropdown on the title lists the four views with the API's count for each (`meta.counts`).

- **Filters** (`filters-sheet.tsx`): status (the default is the open threads, as the server shows them; `pending` no longer exists), the view (including the archived view), one channel, and labels, with a chip for each one that is on.
- **Select several** (long press a row, needs `inbox.conversation.bulk`; `bulk-bar.tsx`, `bulk-sheets.tsx`): mark as read, status, assign, labels, priority, snooze and **mark as spam**, one request for all of them (`POST /inbox/conversations/bulk`); each action also needs its own right. The answer says how many were done, unchanged or failed.
- **Message box**: **saved replies** (the lightning-bolt button, `GET /inbox/saved-replies`, `POST .../:id/use`) and **internal-note mode** (the lock beside the box, `POST .../notes`).

## In the web inbox or the reference app, not built here (recorded, not dropped)

The web inbox is the behaviour to match (feature ids are `TW-TIB1-…` in `docs/threadwise-port/inventory/team-inbox-conversations.md`). The first
table is waiting on the app; the second is waiting on the **backend** (no API route, so there is nothing for the app to call).

### Waiting on the app (the API has it)

| What                                       | Web id           | API                                               | Why it waits                                                                                          |
| ------------------------------------------ | ---------------- | ------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| Sending photos, documents, audio and video | TW-TIB1-019, 020 | `POST /inbox/media`, then a `kind: media` message | needs a picker library (`mobile-native-capability`) and a new development build                       |
| AI rewrite of a reply                      | TW-TIB1-023      | `POST /inbox/ai/rewrite`                          | not started                                                                                           |
| Group chats: who is in the group           |                  | `GET /inbox/conversations/:id/group-members`      | not started                                                                                           |
| A message's delivery log                   |                  | `GET /inbox/messages/:id/log`                     | not started                                                                                           |
| Opening files (documents, videos, audio)   |                  | the media link                                    | they are drawn as tiles; opening or saving needs a download and a viewer (`mobile-native-capability`) |
| Template buttons' links                    | TW-TIB1-018      | the stored template                               | a template message does not store where its buttons go, so they are drawn, not pressable              |
| Linked tasks and bookings on Chat details  | TW-TIB1-012      | `GET /contacts/:id/tasks`, appointments           | the Tasks tab already lists a contact's tasks                                                         |
