# WaDesk table → our schema

WaDesk has 227 tables: 149 carry `workspace_id` (tenant data), the rest are global
or user-scoped. Our rules (CONTRIBUTING, ADR-0002/0004/0009/0016, rule numbers as in
`docs/wadesk-port/target-map.md` §6) turn that into a mechanical translation plus a short list
of decisions a person must make. The script does the mechanical part and tags the decisions.

## 1. Draft

```bash
python3 .claude/skills/wadesk-data-model-port/scripts/mysql2pg_draft.py contacts wa_campaigns
```

Read-only against the local reference DB (needs it prepared: `wadesk-run-reference`; creds via
`WADESK_DB_USER/PASS/NAME`, defaults match that skill). Output is a **draft**: the tenant table
shape, composite FKs to tenant tables, `UNIQUE`s and indexes prefixed with `org_id`, forced RLS
policy, `touch_row` trigger, `CHECK` for former enums, `jsonb` where `JSON_VALID` holds for every
sampled row. It was executed against a real Postgres 16 for all 149 tenant tables (149 created,
149 with RLS enabled and forced) — but "runs" is not "right": every `-- TODO` and `-- NOTE` needs a decision.

Then invoke the `add-migration` skill: `pnpm db:new <name>`, paste the reviewed SQL, run
`check-rls.sh`, mirror in Drizzle (`packages/db/src/schema`) in the same commit. Check the numbering/naming
rule for migrations in `docs/wadesk-port/conflict-map.md` before creating the file.

## 2. Translation rules (what the script applies)

| WaDesk (MySQL)                                                   | Ours (Postgres)                                                                                                                                          |
| ---------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `workspace_id`                                                   | `org_id`, first column of the PK and of every index/unique; drop the old column                                                                          |
| `id` auto-increment                                              | `id bigint GENERATED BY DEFAULT AS IDENTITY`; API exposes only `uuid` (mapper translates)                                                                |
| `tinyint(1)`                                                     | `boolean` (defaults `0/1` → `false/true`)                                                                                                                |
| `int/bigint unsigned`, `smallint`                                | `bigint` / `integer` / `smallint`                                                                                                                        |
| `decimal(p,s)`                                                   | `numeric(p,s)`, money as string end to end (ADR-0012). `float/double` on money is a bug                                                                  |
| `datetime/timestamp`                                             | `timestamptz`; `created_at/updated_at` standardised, plus `row_version integer` (optimistic lock)                                                        |
| `longtext` holding JSON                                          | `jsonb`, and the shape gets a Zod schema in `@crm/contracts`; WaDesk stores JSON as text so check                                                        |
| `enum(...)`                                                      | `text` + `CHECK` (or a Postgres enum, append-only, `-- @no-transaction`); mirror in contracts enums                                                      |
| `deleted_at` (soft delete, 21 tables)                            | gone: hard delete + audit row (ADR-0009). Use `is_archived`/`lifecycle_state` only if the feature needs archive-in-place                                 |
| FK constraint to a tenant table                                  | composite `FOREIGN KEY (org_id, x) REFERENCES t (org_id, id)`; for `ON DELETE SET NULL` write `SET NULL (x)`                                             |
| `*_id` column with no FK (most of them; WaDesk has 115 real FKs) | decide the relation and add the composite FK, or record why it is a loose reference                                                                      |
| `user_id` (owner/creator)                                        | the staff `users (org_id, id)`; WaDesk users are workspace owners, ours are one pool per org                                                             |
| token / secret / password / api key columns                      | AES-GCM encrypted at rest through the provider-adapter credential pattern; never plain text                                                              |
| `*_hash` next to an encrypted PII column                         | WaDesk stores PII encrypted + lookup hash. Decide once (encrypt+hash vs plain under RLS) and ADR it                                                      |
| logs / events / history / messages tables                        | append-only streams: RANGE partition by `created_at`, PK `(id, created_at)`, no FK into them (copy `0006_outbox_audit.sql`, add to `PARTITIONED_TABLES`) |
| global tables (plans, languages, providers)                      | no `org_id`, no RLS, like `permission_defs`, but only if certain; platform-operator tables need the operator pool ADR first (target-map §7)              |
| fulltext keys                                                    | `pg_trgm`/`tsvector` GIN index if the feature really searches                                                                                            |
| duplicate WaDesk indexes                                         | kept once (the script notes the duplicate)                                                                                                               |

## 3. Decisions the script cannot make

1. **Tenant vs global vs user-scoped** for tables without `workspace_id` (78 of 227). If unsure it is tenant.
2. **Which real relation** every loose `*_id` is (read the inventory entry's Data section and the model's `belongsTo`/`hasMany`).
3. **Owner of the table**: one domain owns it (see `ownership.json`); other domains read it through that module's barrel or the outbox, never by importing its repository.
4. **Streams vs plain tables** (volume, retention). Ask what WaDesk does with old rows.
5. **JSON shape**: `jsonb` is only storage; define and validate the shape in contracts (WaDesk never validated it).
6. **Permissions**: new keys go through `rbac-permission`; existing Admin roles do not receive them automatically (locked-role trigger), see target-map §3.

## 4. Never

- Edit an applied migration; never paste the draft unreviewed; never ship a table without running `check-rls.sh` against the live DB.
- Copy WaDesk migration files or seed data. The draft is derived from the schema facts only; write the migration's header comment in your own words (why this table exists).
